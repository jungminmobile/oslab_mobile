# E5b 사전 등록 (결과 보기 전 고정) — Bias Correction으로 RN50 B0 살리기

- 계획서: 프로젝트 문서 `18_E5b_BiasCorrection_실험계획서_2026-10-20.md`. 판정 규칙(3절)은 계획서 그대로 이 파일에 옮긴다.
- 브랜치 `jungmin/e5b-bc` (0db4943 = E10 결과 커밋에서 분기). 이 파일이 들어간 커밋이 사전 등록 해시.
- 측정 기기: 정민 노트북 Core Ultra 7 258V, 충전 중, SAMSUNG MODE, ORT 1.25.0.

## 0. 계획서와 다른 점 (결과 전 기록)
1. **0단계 ② "B0·B2 다시 만들어 sha 확인"**: 어젯밤 E10에서 같은 기기·같은 코드로 다시 만든 결과가 이미 일치했다.
   - B0: `E10_B0` = `9d99f92d2bc3013d…` = 10/18 B0
   - B2: `E10_B2chk` = `687097928a9d…` = 10/18 B2
   - 그래서 기존 파일의 sha256만 다시 확인한다.
2. **대상 층 수**: 계획서 "Conv 53 + AttnPool 4"는 추정이었다. 실제 B0 그래프에서 bias를 찾은 양자화 층은 **59개**다.
   - int32 DQ bias 56개 = Conv 55 + c_proj Gemm 1
   - float Add 상수 3개 = q·k·v MatMul
3. **BC′ 보정 사진**: "시드 1"은 후보 풀 1292장에서 시드 0의 256장을 뺀 나머지 중 시드 1로 256장을 뽑는다(겹침 0 확인).
4. **0단계 ③ 정수 커널 확인 방법**: ReLU가 합쳐진 정수 커널에서는 활성화 전 값을 볼 수 없다. 그래서 각 Conv 뒤 첫 QuantizeLinear 출력(uint8, 정수 커널에서도 그대로 나오는 텐서)을 역양자화한 채널 평균과, FP32의 같은 위치(Q 입력) 평균의 |차이|를 BC 전후로 비교한다(55개 지점).
   - fake-quant 기준은 계획서대로 Conv 출력(ReLU 전) |Δ|다.
5. **세션 일정**: 이번 세션은 2시간 안에 갈 수 있는 단계까지만 한다(0단계 → 1단계 → 2단계 정확도). 2단계 속도·메모리와 3단계는 다음 세션에서 같은 규칙으로 이어서 한다. 판정은 모든 측정이 끝난 뒤에만 한다.
6. **(결과 후 수정, 10/20 04:50) FP32 기준 텐서 버그 수정**: ORT QDQ 양자화기는 Conv 뒤 ReLU를 지우고 Conv 출력 이름을 ReLU 출력 이름으로 바꾼다. 1차 실행은 QDQ의 ReLU 전 값과 FP32의 ReLU 뒤 값을 비교해 Δ가 잘못 들어갔다(정수 커널 이동 41배 악화, cos 0.93→0.06). FP32 기준을 그 ReLU의 입력(= FP32 Conv 출력)으로 고쳤다. 계획서의 방법(ReLU 전 출력 비교)을 그대로 구현한 것이라 판정 기준은 바꾸지 않는다.
7. **(결과 후 수정, 10/20 재개) 0단계 ③ fake 확인 위치**: q·k·v MatMul 3개는 보정을 뒤 Add 상수에 넣는데, 2차 실행은 확인을 Add 앞(MatMul 출력)에서 해서 구조상 줄 수 없었다(fake 86.7%, 3개 빼면 99.95%). 이 3개는 확인 ③의 전·후 |Δ|를 **Add 출력**에서 잰다. 보정 Δ 자체는 계획서대로 MatMul 출력에서 잰다. 기준값(fake 90%, 정수 50%)은 그대로다. 정민이 "실험 이어서 하자"로 다음 세션 계획(STATUS.md 1번)을 승인했다.

## 1. 판정 규칙 (계획서 3절 그대로)
### 주 판정: B0+BC가 B2를 대체할 수 있는가
| # | 조건 |
|---|---|
| ① | 정확도: B2 대비 짝 비교 95% 구간이 0을 포함하거나 0보다 크다 (dev 전체, 고화질 5종, 1000회, 층화) |
| ② | 지연: 1·2·4T 모두 B2 이하 (3세션 중앙값) |
| ③ | 이득: 4T −5% 이상, 또는 peak RSS −5% 이상, 또는 파일 −10% 이상 (B2 대비) |
| ④ | 모든 스레드에서 FP32보다 빠르다 |
| ⑤ | 강건성: B0+BC′도 ①을 만족한다 |

- ①~⑤ 모두 만족 → B0+BC를 RN50 최종 후보로 올린다. B2와 바꿀지는 팀이 정한다.
- ①만 실패하고 B0+BC가 B0 대비 유의하게 좋으면(하한 > 0) → "BC 효과는 있으나 단독으로 B2 대체 불가". E5c(QDrop)는 B0+BC에서 출발한다.
- B0 대비로도 유의하지 않으면 → "BC 효과 없음". E5c는 B0에서 출발한다.

### 참고 판정: B2+BC
- B2 대비 하한 > 0이면 "정확도 개선 선택지"로만 기록한다.

### 0단계 관문 (계획서 4절)
- ① `--zero-delta` 결과 sha256 = B0
- ② BC 후 그래프·가중치·scale·zero point가 B0와 같고 bias만 다르다
- ③ |Δ| 감소율: fake-quant 90% 이상, 정수 커널 50% 이상. 정수 커널 기준 미달이면 멈추고 보고한다.

- 결과 후 기준 변경은 이유를 적고 정민의 승인을 받는다.
