# E14-4 패치 임베딩 Conv → MatMul — 실험계획서 (v3)

## 1. 왜 하는가

- O·F2에서는 MatMul만 INT8이다(`ops-MatMul`). **패치 임베딩 Conv는 FP32로 남아 있다.**
- E12-3(O, 4T, 프로파일): Conv 1개가 **0.85 ms**로 노드 하나로는 가장 길다(전체 약 5%). 1T에서는 "기타" 묶음 2.70 ms의 대부분이다(약 6%).
- 계산량: 64패치 × 3072(=3×32×32) × 768 = 약 1.5억 곱셈. MLP 행렬곱 하나(64×768×3072)와 같다. 그런데 MLP 행렬곱은 INT8 정수 커널로 0.23~0.25 ms, Conv는 FP32라 약 3.5배.
- Conv의 kernel = stride = 32, pad 0, group 1 → "이미지를 32×32 조각으로 자른 뒤 행렬곱"과 **수학적으로 같다**.
- 부수 효과(P2): 가중치 768×3072를 FP32(9.0 MiB) → INT8(2.25 MiB) → **파일 약 −6.75 MiB(약 −7%)**. 10/24 재측정에서 B/32 peak 메모리는 세션 생성 때 나왔으므로 peak도 줄 수 있다.

## 2. 바꿀 곳 (그래프 직접 확인, 10/25, O 기준)

```
image [B,3,256,256] → Conv(W 768×3×32×32, b 768, k32 s32) → Reshape → Transpose → Add(위치 임베딩) → LN / SkipLN (블록 0)
                      └────────── 바꿀 곳 ──────────┘
```

| 항목 | 값 |
|---|---|
| Conv 수 | 1 (`/trunk/patch_embed/proj/Conv`) |
| 입력 | 그래프 입력 `image` 바로 (float, [batch,3,256,256], 값 = pix/127.5 − 1) |
| 가중치 / bias | float32 (768,3,32,32), \|max\| 0.0436 / float32 (768,), \|max\| 1.288 |
| 뒤 연결 | Reshape → Transpose → `/trunk/Add` (위치 임베딩) → 블록 0 LN·SkipLN |
| 첫 QuantizeLinear | 블록 0 LN 출력 (scale 0.0331, zp 125). 즉 패치 임베딩 ~ 첫 LN은 **float 구간** |

F2에서도 같은지 0단계에서 확인한다.

## 3. 바꾸는 방식

| ID | 바꾸는 방식 | 양자화 값 변화 |
|---|---|---|
| F2 (기준) | Conv(FP32) | — |
| **P1** (대조군) | image → Reshape [−1,3,8,32,8,32] → Transpose (0,2,4,1,3,5) → Reshape [−1,64,3072] → **MatMul(FP32, Wm = W.reshape(768,3072).T)** → Add(bias) | 없음 |
| **P2** (본안) | image → **Add(+1.0) → QuantizeLinear(U8, scale 2/255, zp 0) → DequantizeLinear** → (P1과 같은 자르기, float) → **MatMul ← DequantizeLinear(INT8 가중치)** → Add(b') | 이 MatMul 하나만 새로 양자화 |
| **P2b** (변형) | image → Add(+1.0) → QuantizeLinear → **자르기(uint8로)** → DequantizeLinear → MatMul ← DQ(INT8 가중치) → Add(b') | P2와 숫자 같음 (정수 Transpose는 정확) |

**P2·P2b 입력 양자화 (무손실, 보정 데이터 필요 없음)**
- 입력 x = p/127.5 − 1, p는 0~255 정수 → x + 1 = p/127.5 → (x+1) / (2/255) = **p**. 그래서 `Q(x+1; scale 2/255, zp 0)` = p가 **정확히** 나온다 (float 오차 ~1e-7은 반올림에서 사라짐).
- v1의 `scale 2/255, zp 128` 방식은 버린다: p − 127.5가 늘 x.5라 모든 픽셀에서 반 칸 오차 + 짝수 반올림으로 이웃 두 픽셀이 합쳐져 사실상 7비트가 된다 (리뷰 1번).
- 0단계에서 입력이 정말 정수 픽셀인지 확인한다 (G0 ⑥). 아니면 4절 분기.

**P2·P2b 가중치·bias**
- 가중치: **기존 MatMul 가중치와 같은 형식**(dtype, per-channel 축, zp, reduce_range 여부)을 0단계에서 fc1 가중치 DQ로 확인하고 그대로 따른다. 값은 FP32 Wm에서 채널별 \|max\| 대칭.
- **b' = b − W_dq.sum(axis=0)** (W_dq = INT8 가중치를 다시 float로 바꾼 것, 3072×768 → 출력 채널별 합, float64로 계산 후 float32). 이러면 모델 출력 = **W_dq·x + b** (입력 오차 0, 가중치 INT8 오차만 남음).
  - 리뷰는 원래 FP32 W로 b'를 계산하자고 했지만, 그러면 출력 = W_dq·x + b + (W_dq − W)·1 이 되어 가중치 오차가 (x+1) 크기(0~2)로 들어간다. W_dq로 계산하면 오차가 (W_dq − W)·x (x는 −1~1) 크기로 더 작다. x+1 계산의 float 오차는 Q 반올림에서 이미 사라지므로 상쇄할 필요가 없다.
- 다른 Q/DQ 노드와 상수는 건드리지 않는다.

**공통 규칙**
1. 위치 임베딩 Add의 다른 입력이 상수면 bias(b 또는 b')를 그 상수에 미리 더해 Add 1개로 줄여도 된다 (P1·P2·P2b 같은 방식). 아니면 bias Add를 따로 둔다.
2. Reshape 모양은 batch를 −1로 둔다. batch 1·2 모두 확인.
3. 비교용으로 **패치 MatMul 출력을 그래프 출력으로 하나 더 꺼낸 측정용 사본**을 만든다 (G2(a) 전용, 지연·메모리·정확도에는 안 씀). **비교값 = 꺼낸 MatMul 출력 + b (P1) 또는 + b' (P2·P2b)** (numpy float32), 이것을 F2의 Conv→Reshape→Transpose 출력과 비교한다. P2의 MatMul 출력은 W_dq·(x+1)이라 b'를 더해야 W_dq·x + b가 된다. bias를 위치 임베딩에 합치지 않고 따로 둔 경우에는 bias Add 출력을 직접 꺼낸다.

**기대 효과 (보수적)**
- P1: Conv도 안에서 im2col + FP32 행렬곱이라 **0 ~ −1%**.
- P2: Conv 0.85 ms → INT8 행렬곱 약 0.25 ms면 최대 −0.6 ms(−3.7%). 여기서 Add(+1)·Q·float Transpose 비용(약 0.1~0.2 ms)을 빼면 **4T −2 ~ −3%, 1T −3 ~ −4%**. (10/24 추천표의 −3~4%는 이 추가 비용을 빼기 전 값)
- P2b: float Transpose 대신 uint8 Transpose(데이터 1/4)라 P2보다 조금 더 빠를 수 있다. ORT가 정수 커널로 합치는지가 관건(G1 ⑤).

## 6. 판정 규칙 (사전 등록)

비율 = 같은 세션 안의 **F2 대비**, 3세션 중앙값.

| 판정 | 조건 |
|---|---|
| **채택 후보** | ①~⑤ 모두 만족 |
| 효과 없음 | ②만 불만족, 또는 G3에서 멈춤 |
| 기각 | ④ 또는 ⑤ 불만족 |

| # | 조건 |
|---|---|
| ① | G0~G3 통과 |
| ② | **4T p50 ≤ −1.5%** |
| ③ | 1T·2T p50 **+2% 이내** |
| ④ | 정확도: dev 전체 고화질 **F2 대비 95% CI 하한 > −0.3%p** (CIFAR A는 따로 기록) |
| ⑤ | peak 메모리 **+2% 이내** |

**고르는 법**
- 여러 개가 채택 후보 → 4T p50이 가장 낮은 것. 차이 1% 이내면 **P1 > P2 > P2b** 순 (새 양자화 없음 > 그래프가 단순함).
- P2 계열이 채택되면 보고서에 "첫 층 양자화(입력 무손실, 가중치 INT8)" 정확도 비용을 따로 적는다.

**기준 −1.5% 근거**: Conv가 전체의 약 5%라 다 없애도 최대 −5%. P2 기대치 −2~3%의 절반 남짓. E14-1(−1.5%)과 같다.

**F2가 팀 결정에서 채택되지 않으면**: 바꾼 부분은 GELU와 겹치지 않는다. 그때는 O 위에 같은 변경을 다시 적용해 지연만 1세션 확인한다 (판정은 이 문서 결과를 따른다).
