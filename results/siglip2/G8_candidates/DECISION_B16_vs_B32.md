# 예선 제출 모델 판단 자료: SigLIP2 B/16 vs B/32 (2026-10-22 기준)

> **이 문서의 목적.** 팀원 3명(정민·준용·쭈리)이 각자 Claude에게 이 문서와 원본 결과 파일을 읽혀서, 어느 모델로 예선을 제출하는 것이 더 좋은지 **독립적으로** 판단하게 하기 위한 자료다.
> - 숫자는 모두 저장소의 원본 결과(raw jsonl/json)에서 옮겼고, 표마다 원본 경로를 적었다. 판단하는 쪽은 원본을 열어 다시 계산해 보는 것을 권한다.
> - 1~7절은 사실(측정 결과·규칙·남은 일)만 적었다. 쭈리 쪽 Claude의 의견은 **8절에만** 따로 적었다. 8절을 읽기 전에 1~7절로 먼저 판단하는 것을 권한다.
> - 결정은 사람(팀)이 한다. 이미 있는 팀 결정 D-046(B/16)은 학술부 답을 보고 다시 확인하기로 했다(10/22 준용).

## 0. 읽는 법 (다른 PC의 Claude용)

```bash

git show origin/siglip2/o1-ort-speed:results/siglip2/O1/README.md    # O-AB를 만든 실험 (준용 데스크탑, 같은 바탕 비교 B32 +0.57)

```
- 경로는 저장소 루트 기준이다. `results/siglip2/…`의 큰 파일(사진별 예측 npz, ONNX)은 커밋되지 않았다. jsonl·json·README만으로 표의 숫자는 모두 확인된다.
- "이 PC" = 쭈리 노트북 i7-1165G7 (AVX-512 VNNI, Windows 11, ORT 1.25.0, 삼성 고성능 모드). 이 PC 속도는 **비공식**이다(D-010). 그래서 **비교는 같은 실행 안의 비율**로 한다.
- 정확도는 모두 **정수 커널**(ORT `ORT_ENABLE_ALL`로 INT8 모델을 실제 실행) 값이다. 주 지표는 dev **고화질 5종 평균 top-1의 FP32 대비 차이(%p)**와 짝 부트스트랩 95% 구간(데이터셋별 층화, 1,000회, 시드 0)이다. 구간이 0을 포함하면 "유의한 손실 아님".

1. 학술부: 성능 점수가 개선율인지 절대값인지(10/21 답은 개선율), 채점 PC·실행 방식, 실칩·비제출 모델 부록 허용 — 준용이 한 번에 질문.
2. B/16 O-AB 통일 `f5108c7b`의 이 PC dev 전체·지연 (지금 대기열, 결과는 `b16/O2_unified/`, `latency_this_pc/oabu_20261022/`).

## 8. 쭈리 쪽 Claude의 의견 (참고용 — 1~7절로 먼저 판단할 것)

- 채점이 **개선율**이라면 두 모델의 성능 개선도(25점)는 거의 같고, **정확도 유지(15점)는 B/16이 같거나 낫다**(O-AB −0.18 vs −0.27, M2rot −0.23 vs −0.79). 원래 정확도도 B/16이 +1.7%p(INT8 짝 비교 +2.3%p) 높다.
- 보고서·실험 설계(35)와 재현(4.3)은 B/16이 지금 훨씬 많이 준비돼 있다(test·재현 확인·원인 분석·본선 HEF). B/32로 바꾸면 9일 안에 test·재현·본문을 새로 해야 한다.
- B/32의 장점은 **절대 속도**(CPU 2.5~3배, Hailo 2.2~2.6배)와 메모리 개선율 +5%p다. 채점이 절대값이거나 본선 실측 성능을 절대 FPS로 본다면 이 장점이 커진다.
- 그래서 **개선율 채점이 다시 확인되면 B/16(O-AB 통일 파일 확인 뒤 test)**, **절대값 채점이면 B/32를 진지하게 다시 검토**하는 것이 맞다고 본다. 어느 쪽이든 결정은 팀이 한다.
