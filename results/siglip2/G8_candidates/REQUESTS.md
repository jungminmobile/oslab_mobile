# G8 팀원 요청 목록 (2026-10-20, 쭈리 전달용)

후보: SigLIP2 B/16 · SigLIP2 B/32 · RN50. 실험을 모두 마친 뒤 후보표를 보고 팀이 제출 모델 하나를 고른다. 보고서는 그 뒤에 쓴다.

## 준용
1. **Hailo 속도 개선 (본선 직결)**: B/16 M2rot_D256L1과 B/32 M에 Zoo `.alls`의 `resources_param`(compute 1.0, control 0.95, memory 0.75)·`bucket`을 다시 넣어 재컴파일 (A만 / B만 / A+B). 실칩 dev 전체 정확도와 배치 1 지연(G6 측정 규칙). 판정 기준은 결과 전에 고정. 근거: G6에서 S1B16 D − V가 컨텍스트 17로 같은데 지연 +44.5%.
2. (1의 효과가 작으면) 16비트 층 줄이기(conv41, 블록 0 fc), Hailo INT4 가중치(a8_w4, MLP fc1부터).
3. **CPU로 넘어가는 층 확인** (보고서 3.3): B/16 M2rot_D256L1·B/32 M HEF에서 모든 층이 칩에서 도는지, 호스트 쪽 전처리·후처리가 있는지 (profiler·parse-hef).
4. ARM(Orin) 정확도: B/16 M2rot_ort와 B/32 CPU 주 후보를 `portable_eval` 묶음으로 (묶음은 쭈리 쪽에서 Release로 올림, 각 10분).
5. 다른 x86 확인 (285K): B/32 CPU 주 후보 같은 묶음.
- 참고: 쭈리 실험 브랜치 `siglip2/g8-candidates`는 준용 브랜치 `g3rq-m2rot-ort`·`g6-zoo-transfer`의 코드를 합쳐 쓰고, `s2common`에 입력 크기 상수(S.IMG 등, 기본 B/16 그대로)를 더했다. 그 코드가 바뀌면 알려 주기.

## 정민
1. **RN50 최종 후보 수치**를 후보표 열에 맞춰: dev 고화질 5종 평균 top-1(절대값)·Δ[95% 구간]·cos·CIFAR A Δ, 크기 MB, 파라미터, GFLOPs, 지연(노트북 스레드 1·2·4, FP32 대비, 고성능 모드), peak 메모리, Hailo 상태(컴파일 여부, 실칩/에뮬레이터 정확도·지연).
2. **SigLIP2 공식 지연** (D-010): B/16 M2rot_ort와 B/32 주 후보를 노트북에서 같은 스크립트로 (묶음·명령은 쭈리가 전달, 약 1시간).
3. PR 통합 리뷰 (main 병합 → 학술부 재현 확인용), smoke test.
