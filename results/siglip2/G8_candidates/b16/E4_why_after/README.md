# E4: 회전·M2가 거대 활성값을 실제로 없앴는가 (계획, 2026-10-21 결과 전 고정)

- 계기: 보고서 v4 독립 검토 — "M2와 회전으로 0으로 반올림되는 손실이 사라졌다"는 문장의 직접 근거가 없음 (0으로 반올림되는 비율을 다시 재지 않음).
- 방법 (`siglip2/s2_why_after.py`): 2×2와 같은 FP32 그래프 4개(원래 / 회전만 / M2만 / 회전+M2, A1에서 이 PC가 만든 `onnx_g8`)의 MatMul 입력 활성값 79개를 dev 64장(Pets·Caltech 앞 32장씩, G3_why와 같은 사진)으로 잰다.
  - 텐서당 눈금 1개(MinMax, UINT8 비대칭, 64장 전체 범위)일 때 **0으로 반올림되는 원소 비율**, 사진마다 max|x|/mean|x|(쏠림)
- **판정 없음 (기록만)**. 보고서 6.6·5.3의 해당 문장을 결과대로 고친다. 예측(가설): 원래·회전만은 블록 5 이후 fc2 입력에서 비율이 높고, M2를 쓴 두 그래프에서 크게 낮아진다.

- 회전은 잔차 흐름에서 오는 입력(fc1)의 0 반올림을 거의 없앤다 (채널 축). fc2 입력(MLP 은닉 3072차원)은 회전 대상이 아니라 그대로다.
- **예측(M2가 fc2 입력의 0 반올림을 크게 줄임)은 블록 5에서만 맞고 블록 8~11에서는 틀렸다.** 그런데 M2 모델의 실제 INT8 정확도는 좋다(−0.62) → "0으로 반올림되는 비율"은 GELU 출력처럼 원래 0 근처 값이 많은 텐서에서 정확도와 바로 이어지지 않는다.

## E4b 결과 (Percentile 99.999 눈금, 64장, `why_after_pct.jsonl`·`why_after_pct_summary.json`, 커밋 af38821, dirty 아님)

**8비트 활성값의 출력 SNR (dB, 높을수록 좋음 — 가중치는 FP32, 활성값만 그 눈금으로 8비트)**

| 층 | 원래 | 회전만 | M2만 | 회전+M2 |
|---|---|---|---|---|
| fc2 블록 5 | **10.7** | 10.7 | 21.6 | 21.6 |
| fc2 블록 9 | **0.3** | 0.3 | 27.0 | 27.0 |
| fc2 블록 10 | **7.9** | 7.9 | 40.1 | 40.1 |
| fc2 블록 11 | 13.5 | 13.5 | 18.3 | 18.3 |
| fc2 블록 0~4·6~8 | 23.9~34.7 | 같음 | 같음 | 같음 |
| fc1 블록 0~11 (LayerNorm 뒤) | 26.9~37.1 | **32.4~45.6** | 27.8~39.5 | **32.4~45.4** |
| QKV 블록 0~11 | 26.5~32.0 | **41.0~46.6** | 26.5~32.0 | **41.0~46.6** |
| 가중치 MatMul 전체 최솟값 / 평균 | 0.3 / 30.6 | 0.3 / 36.2 | 18.3 / 32.3 | **18.3 / 37.6** |

- **M2(토큰 축)**: 거대 값이 있는 fc2(블록 5·9·10)의 출력 SNR을 0.3~10.7 dB → 21.6~40.1 dB로 올린다. 원래 모델에서 이 층의 |x| 최댓값은 사진 64장 모두 sink 토큰(블록 5: 패치 55, 블록 9~11: 패치 13·55)에 있었고, M2 뒤에는 최댓값 위치가 사진마다 흩어진다(고정 sink가 사라짐).
- **회전(채널 축)**: 잔차 흐름에서 오는 입력(fc1·QKV)의 출력 SNR을 약 10~15 dB 올린다. MLP 은닉(fc2 입력)은 회전 대상이 아니라 그대로다.
- 둘을 합치면 모든 가중치 MatMul의 출력 SNR이 18 dB 이상, 평균 37.6 dB — 2×2 정확도(A1: 원래 −63.5 → M2 −0.62 → 회전+M2 −0.31)와 같은 순서다.
- **원인 설명 정정**: Percentile 눈금에서도 블록 8~11 fc2 입력은 M2 뒤에 96~99%가 0으로 반올림되지만 출력 SNR은 높다. fc2 입력(GELU 출력)은 원래 0 근처 값이 대부분이라, "0으로 반올림되는 비율" 자체는 손실의 원인이 아니다. 손실과 이어지는 것은 **sink 토큰의 거대 값이 눈금을 넓혀 그 층 출력 오차가 커지는 것**(블록 9 SNR 0.3 dB)이다. G3_why의 개입 실험(거대 값 토큰을 빼고 눈금을 정하면 cos 0.997)과 같은 결론이다. 보고서 2·5.3·6.6의 "보통 토큰 값의 84~99%가 0으로 반올림 → 망가짐" 문장을 이 결과로 고친다.
- 참고: 블록 8 fc2의 최댓값은 패치 13(83%)인데 M2는 패치 13을 블록 9부터 바꾸므로 블록 8은 그대로다(SNR 25.8 dB, 문제 수준 아님).
