## 결론
- **15% 이상 빨라진 구성이 없다 → 예선 모델(M2rot_ort)은 그대로.** test를 다시 쓸 이유가 없다.
- (a) QOperator는 정확도는 같고 2% 빠르지만 측정 흔들림(반복 사이 표준편차 1~2 ms) 수준이다.
- (b)(c)는 정수로 바꾼 연산 앞뒤에 ORT가 **DequantizeLinear를 오히려 더 넣어**(66 → 118·137) 빨라지지 않았다. 정수로 계산할 수 없는 연산(LayerNorm·GELU 등)이 사이사이에 있어서, 정수 구간이 짧게 끊기기 때문이다.
- (c)는 cos가 0.976 → 0.926으로 떨어졌다. 잔차 덧셈(Add)·Mul·패치 Conv를 함께 정수로 바꿨으므로 어느 것 때문인지는 나누지 않았다. 가설: 잔차 흐름의 큰 값이 8비트 눈금 하나에 들어가지 못함 (원인 분석과 같은 이유, 검증 안 함).
- 정리: CPU에서 남은 Q/DQ 비용(약 13%)은 "정수 MatMul 사이에 실수 연산(LayerNorm·GELU)이 끼는 구조"에서 오는 것으로 보이며, 저장 형식만으로는 줄지 않았다. Softmax는 ORT가 이미 정수(QLinearSoftmax)로 바꾼다. LayerNorm·GELU를 정수로 하는 연산은 이번 ORT 양자화 경로에서 생기지 않았다 (가설 수준, 다른 경로는 확인 안 함).
