# SigLIP2 후보표 (팀 선택용, 2026-10-14 초안)

이 표는 **선택을 돕는 자료**다. 최종 트레이드오프 지점(정확도·속도·용량)은 Claude가 정하지 않고 팀이 상의해서 고른다 (CLAUDE.md).
모든 정확도는 정수 커널(ORT) 또는 DFC 양자화 에뮬레이터 값이다. 이 PC 지연은 **비공식**이다 (D-010).

- **지연** (비공식, 이 PC, 세 번 측정: `../G3_cumulative/speed`(10/14 17:31), `speed_qkvu8`(23:50), `speed_night`(10/15 04:18)):

## 2. Hailo DFC 구성 (결과표 S-C·S-D 후보, 에뮬레이터)

정확도: dev 6종 × 앞 200장, DFC `SDK_QUANTIZED` 에뮬레이션. Δtop-1은 FP32 대비 짝 부트스트랩이다 (`../G4_dfc_screen`). 같은 200장의 ORT fc2L2는 +0.3 [−0.6, +1.2], cos 0.956이다.

- C와 D는 동률이다 (+0.3 [−0.4, +1.1]). 보정 64장인 C·D는 ORT fc2L2보다 유의하게 낮다 (1.4~1.7%p). **보정 256장 D는 ORT fc2L2와 동률이다** (+0.5 [−0.7, +1.7], `../G4_dfc_screen` 6-2절). D64→D256 직접 차이는 +0.9 [−0.3, +2.2]로 아직 유의하지 않다.

- **dev 전체 (10/16)**: C256L1 −1.56 [−2.09, −1.03], D256L1 −1.19. 둘의 차이 +0.38 [−0.03, +0.76]은 경계 동률 → **D-032 확정: C256L1** (D-038 (가) 규칙, D256L1은 정확도 우선 대안). `../G4_dfc_full` 7절
- **C256L1과 D256L1은 동률이다** (+0.4 [−0.2, +1.0], 예측 일치 98.5%, `../G4_dfc_screen` 6-4절). cos는 D256L1이 조금 높다 (0.967 vs 0.964). C256L1은 HEF가 2.7 MB 작고 컨텍스트가 1개 적다 (97.1 MB·16 vs 99.8 MB·17, 둘 다 컴파일 확인, `../G4_compile`).
- 실칩 지연·처리량은 본선 Pi 5 + Hailo-10H에서 잰다 (D-015). 참고로 Hailo 공식 SigLIP(v1) B/16은 33.0 FPS다 (Model Zoo).
- DFC 행의 `dirty: true`는 WSL git의 CRLF 오인이다 (`../G4_dfc_screen` 5절). 다시 돌리지 않는다 (D-033 확정).

## 3. 팀이 정할 것

> **10/15 확정**: 1·2번 → **fc2L2 U8 + reduce_range** (D-030·D-031, S8은 대안 행). 4번 → 다시 돌리지 않음 (D-033). 5번 → D-034. 3번 → **C256L1** (D-032, 10/16, 경계 동률). 4비트 → **넣지 않음** (D-039, 10/16: 정확도 동률·크기 −30%지만 4스레드 지연이 U8+rr의 약 2배, `../G3_w4`). **남은 결정 없음 — 최종 동결 가능.** 아래는 결정 전 기록이다.

1. **S-B(ORT 최종)**: fc2L7 / L4 / L2 / L2 U8 / L2 U8+reduce_range 중 하나. S8 세 개는 정확도 동률이다. 4스레드에서 FP32보다 느린지는 이 PC의 세 측정에서 +2.5% / −10.6% / +0.5%로 바뀌었다 (공식 측정 필요). U8은 세 측정 모두 지연이 FP32의 약 절반이지만 정확도가 −0.90%p(S8보다 −0.41%p 유의)다.
2. **S8 vs U8 (D-023 재검토)**: 정확도(S8 우세, 0.41%p) 대 지연(U8 약 2배 빠름). **QKV 투영만 U8로 둔 모델은 U8과 예측이 완전히 같았다** (`../G3_cumulative/full_qkvu8`) → S8과 U8의 차이는 전부 QKV 정수 경로에서 나오고, "S8 정확도 + U8 속도"를 이 방법으로 함께 얻을 수는 없다. reduce_range·U8U8 대책(`../G3_cumulative/qkv_precision`)은 둘 다 S8과 동률이 됐지만 U8보다 유의하게 좋지는 않았다. reduce_range는 U8과 같은 속도, U8U8은 느리다. x64quantprecision은 이 PC(VNNI)에서 출력이 같다.
3. **S-D(DFC 최종 `.alls`)**: C / D / D + 보정 256장 / **D + 보정 256장 + 최적화 수준 1 (cos 0.967, 가장 높음)** / C + 보정 256장 + 최적화 수준 1 (cos 0.964, D256L1과 top-1 동률, 97.1 MB·16 컨텍스트로 2.7 MB 작음). 정민 노트북 교차 확인(D-027) 시점.
4. DFC 스크리닝 dirty 오표시 3행을 다시 돌릴지.
5. 원인 분석(`../G3_why`)을 보고서에서 어떻게 쓸지. (D-034: 예선은 모델 하나 제출이라 "CNN vs Transformer" 서사는 쓰지 않는다. "기법의 기술적 깊이" 근거로 쓴다)
