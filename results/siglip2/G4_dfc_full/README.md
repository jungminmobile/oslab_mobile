# G4 DFC dev 전체 평가: D256L1 (2026-10-15)

**결론: D256L1(구성 D + 보정 256장 + 최적화 수준 1)을 dev 전체 5,923장으로 재면 고화질 Δtop-1 −1.19 [−1.78, −0.62]로 FP32 대비 유의한 손실이다. cos는 0.967로 가장 높다.**
- 200장 표본(−0.4 [−1.4, +0.6])보다 나쁘다. 그러나 표본 구간 안의 값이고, ORT 대비 차이는 표본 +0.7 [−0.5, +1.9] → 전체 +0.69 [+0.12, +1.31]로 점추정이 같다. 구간만 좁아져 유의해졌다.
- ORT fc2L2 S8(−0.50)·fc2L7(−0.46)보다 유의하게 낮고, ORT U8+reduce_range(−0.78)와는 동률이다 (+0.40 [−0.19, +1.07]).

## 1. 왜 했나

G4 스크리닝(`../G4_dfc_screen`)은 데이터셋마다 앞 200장(고화질 1,000장)이라 95% 구간 폭이 ±1%p였다. 그 표본에서 D256L1·C256L1·ORT는 모두 동률이었다.
DFC 최종 구성(D-032)을 고르고 ORT 후보와 비교하려면, ORT 후보처럼 dev 전체(고화질 4,923장 + CIFAR A 1,000장)로 재야 한다.

## 4. 해석

- **200장 표본이 D256L1에 유리하게 뽑혔다.** 앞 200장 Δ는 −0.4, 나머지 3,923장은 약 −1.4다. ORT S8도 같은 방향이다 (앞 200장 +0.3, 전체 −0.5). 그래서 두 구성의 **차이**는 표본(+0.7)과 전체(+0.69)가 같다. 구간별 실행 문제(가설 2)였다면 차이도 바뀌었어야 한다 → 표본 변동(가설 1)으로 본다.
- **cos와 top-1이 엇갈린다.** D256L1은 cos가 가장 높은데(0.967 vs ORT 0.956) top-1은 더 낮다. cos는 평균적인 임베딩 충실도이고, top-1은 클래스 경계 근처 사진에서 순위가 뒤집히는지에 좌우된다. 바이어스 보정은 평균 이동을 줄여 cos를 올리지만, 경계 근처의 작은 오차(특히 Food처럼 클래스가 비슷한 데이터셋)는 남는 것으로 보인다 (추정).
- **Food가 가장 크다** (−2.64, ORT −1.52). 101개 음식 클래스가 서로 비슷해 작은 임베딩 오차에도 순위가 바뀌기 쉽다 (추정).
- PRD 주 지표(고화질 Δtop-1)로 보면 Hailo 경로는 ORT S8보다 약 0.7%p 손해다. 다만 ORT U8+reduce_range(속도 후보)와는 동률이다.

## 5. 기록상 주의

- start=800 첫 실행 OOM은 숨기지 않는다 (`log_D256L1_s800.txt`). 재실행은 같은 HAR·같은 구간이고 데이터셋 묶음만 나눴다.
- start=200~1000 구간의 `screen.jsonl` 행은 `hr_sets` 필드가 생기기 전 스크립트 복사본으로 돌았다 (구간 요약 hr_cos·hr_dtop1은 그 구간에 있는 데이터셋만의 평균). 최종 수치는 합친 npz에서 다시 계산한 위 표를 쓴다.
- C256L1 dev 전체 평가는 진행 중이다 (`siglip2/hailo/g4_more7_wsl.sh`, 10/15 19:58 시작).
- **`commit` 필드 주의 (10/15 독립 검토 지적)**: WSL 체인은 시작할 때 `s2_dfc_screen.py`를 `~/`로 한 번 복사해 쓰는데, 각 행의 `commit`은 그 행을 실행한 시점의 저장소 HEAD다.
  그래서 `screen.jsonl`의 s200 행은 `5e3a287`, s400·s600·s1000 행은 `ff07336`으로 적혀 있지만, **실제로 실행된 코드는 체인 시작 커밋의 복사본**이다 (g4_more4: `e8dcff1`, g4_more6: `41071d7`). 두 커밋 사이에 바뀐 것은 행 요약 필드(`hr_sets`·`sets`)뿐이고 계산은 같다.
  앞으로는 행에 실행한 스크립트의 sha256(`script_sha256`)을 같이 기록한다.
- **재현성 근거**: OOM으로 죽은 첫 start=800 실행의 로그(`log_D256L1_s800.txt`)에 찍힌 5종 값이 3종씩 나눈 재실행(s800a·s800b)의 값과 완전히 같다.
