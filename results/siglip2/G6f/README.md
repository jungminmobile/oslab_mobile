# G6f: B32 정밀도 축의 Hailo 속도 상한 + G·F 조합 (설계 2026-10-21)

> 상태: **설계 (결과 전 고정).** 1~4절은 빌드 전에 커밋한다. 결과는 5절부터 적는다.
> 브랜치 `siglip2/g6f-ceiling` (`siglip2/g6d-speed2` 593e8ab에서 만듦), worktree `~/oslab_g6f`, AGX 폴더 `~/ssd/junyong/hailo_g6f`. 담당: 용 (용 요청). **test는 쓰지 않는다.**
> 질문: G의 −5%(배치 1 15.66 ms, Z 16.49 ms)가 정밀도만 바꿔서 갈 수 있는 끝에 가까운가? G와 F를 합치면 더 빨라지는가?
> 배경 (G6d): Z 16.49 ms (컨텍스트 12), G 15.66 ms (11), F 16.54 ms (13), M_both 18.38 ms (13).

## 1. 구성 (B32, `alls/`)

| 순서 | 이름 | 원본 | .alls | 만드는 방법 |
|---|---|---|---|---|
| 1 | **GF** | G optimized HAR (`~/siglip2_work/g6/dfc/b32_G/g6_b32_G_optimized.har`) | `g6f_b32_GF.alls` = G6d `g6d_b32_G.alls` + G6d `g6d_b32_F.alls`의 `allocator_param`·`context_switch_param` 두 줄 | **compile만** |
| 2 | **ALL8** | G6 M ONNX (`g6_b32_m2rot_b1.onnx`, `a0eb502b…`), 보정 256장 (`calib256_s0_zoo256_nhwc.npy`, `d77eed13…`, G와 같음) | `g6f_b32_ALL8.alls` = G .alls에서 `precision_mode=a16_w16` 두 줄(패치 경로 `norm1, conv1, format_conversion1`, 잔차 덧셈 26개)을 뺌. `resources_param`은 유지 → 모든 층 기본 8비트 | parse부터 |
| 3 | **ALL8F** | ALL8 optimized HAR | `g6f_b32_ALL8F.alls` = ALL8 + F의 두 줄 | **compile만** |

- 스크립트: `g6f_build.sh`(순서대로, ALL8이 실패하면 ALL8F 건너뜀), `g6f_compile_only.sh`(G6d와 같음, 기록 파일만 G6f). DFC 5.4.0, `dfc.lock`, 여유 메모리 ≥ 20 GB.
- compile 상한 2시간. 넘거나 실패하면 그 구성만 실패로 기록한다. 실패 때만 최소한으로 고치고 기록한다.
- ALL8은 속도 상한을 재는 구성이다. **정확도는 판정하지 않는다** (참고 기록만).

## 2. 측정

### 2-1. 정확도 (AGX 실칩, G6 eval 코드·캐시·분류기, dev 6×200 = 데이터셋마다 앞 200장)

- **GF**: G의 실칩 dev 임베딩(G6d `eval_b32_G`) 앞 200장과 비트 비교한다. 1,200장 모두 같으면 G 값(dev 전체)을 쓴다. 다르면 GF dev 전체 eval을 하고 G6d 방식으로 쌍 비교한다.
- **ALL8F**: ALL8과 비트 비교만 한다 (compile만 바뀜).
- **ALL8 (참고)**: dev 6×200 실칩에서 FP32 대비 고화질 Δtop-1(5개 데이터셋 평균)과 cos(평균·최소)를 잰다. 같은 optimized HAR의 에뮬레이터(SDK_QUANTIZED, `g6f_emulate.py`, 입력 0~255 픽셀) 6×200 출력과 비교한다: 에뮬레이터 cos·top-1, cos(에뮬레이터, 실칩).
  - **실칩 정상 판단:** 실칩의 FP32 대비 고화질 cos가 에뮬레이터보다 0.02 넘게 낮지 않으면 정상으로 본다 (G6c: 정상 HEF의 에뮬레이터·실칩 FP32 cos는 같은 수준, 무너진 HEF는 0.4대).
  - 같은 방식으로 G도 에뮬레이터를 돌려 대조군으로 쓴다 (G 실칩 6×200과 비교).

### 2-2. 속도

- 같은 세션에서 번갈아 잰다: **Z, G, GF, ALL8, ALL8F** (실패한 구성은 빠짐). 배치 1·8 × 3세션, HEF마다 칩 < 64.6 °C에서 시작. 끝나고 `run2 -t 10`, `hailortcli parse-hef`(컨텍스트·크기).
- 코드: G6 `g6_hailo_chip.py`(G6d와 같은 파일) + `run.sh`를 AGX `hailo_g6f`로 복사한다. run.sh에서 바꾸는 것은 작업 폴더와, 기본 꺼진 `EVAL_K`(eval 데이터셋마다 앞 k장, `--k`로 전달)뿐이다.

### 2-3. 동시 실행 (G6e가 같은 AGX를 씀)

- 칩 단계(eval, 속도) 시작 전마다 AGX에서 다른 Hailo 프로세스와 G6e의 run.sh가 없는지 본다. 있으면 10분 간격으로 확인하며 기다린다 (상한 3시간, run.sh 자체의 대기도 3시간).
- 칩 단계 동안 감시 스크립트(`g6f_watch.sh`)가 30초마다 AGX의 Hailo 관련 프로세스 중 **작업 폴더가 `hailo_g6f`가 아닌 것**을 시각과 함께 적는다.
- 어떤 bench 세션(배치·세션 번호 하나 = HEF 5개 한 바퀴) 시간대에 외부 프로세스가 적혀 있으면 그 세션 값은 버리고, 같은 세션을 다시 잰다. eval은 출력이 결정적이라 겹쳐도 버리지 않고 기록만 한다.

### 2-4. 안전 (G6d와 같음)

- 시작 온도 < 64.6 °C, 단계마다 95 °C 넘으면 즉시 멈춤 (`HOT_STOP=95`), 측정 중에는 온도를 읽지 않는다.

## 3. 기록할 것 (판정 대신, 결과 전 고정)

| 항목 | 정의 |
|---|---|
| **정밀도 축 상한** | ALL8과 ALL8F 중 배치 1 지연이 짧은 쪽 (= 상한 HEF). 값과 Z 대비 비율 |
| **G가 상한까지 간 비율** | (Z − G) / (Z − 상한), 배치 1, 같은 세션 평균. 분모가 0 이하이면 "정의 안 됨"으로 적는다 |
| **GF** | GF가 G와 출력 비트 동일 **그리고** 배치 1 지연이 G 대비 −2% 이상 줄면 **"B32 최종 후보: GF"**로 적는다. 아니면 그 이유(비트 다름 / 속도 차이 부족)를 적는다 |
| **ALL8 정확도 (참고)** | 실칩 6×200 고화질 Δtop-1 점추정이 −3.00%p 이상이면 **"잔차 8비트 실험 가치 있음"**으로 적는다 (실험은 하지 않음). 6×200은 표본이 작아 95% 구간(`s2_paired_ci.boot_hr`)도 함께 적는다 |
| **컨텍스트-지연** | 이번 HEF와 G6d HEF(Z·V·M_both·Dmax2·S1·S2·F·Vrot·G)의 (컨텍스트 수, 배치 1 지연)을 표로 만든다. 최소제곱 기울기(ms/컨텍스트)를 이번 세션 값만으로, 그리고 G6d 값까지 합쳐서 따로 구한다. 컨텍스트 수 외의 차이(정밀도·compile 설정)가 섞여 있어 인과가 아닌 관찰로 적는다 |

- 지연은 3세션 평균, 세션 사이 범위도 적는다. 이 정의는 결과를 본 뒤 바꾸지 않는다.
