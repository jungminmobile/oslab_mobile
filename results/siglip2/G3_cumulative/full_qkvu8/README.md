## 해석
- x86 ORT에서는 S8 활성값도 실행 때 U8S8로 바뀐다 (PRD 3절). 그래서 QKV 말고 나머지 층의 S8/U8 차이는 예측에 영향이 없다.
- **S8과 U8의 정확도 차이(−0.41%p)는 전부 QKV 투영 MatMul에서 나온다.**
  - S8에서는 QKV가 정수로 합쳐지지 않는다. 역양자화한 값으로 float 계산하는 셈이다.
  - U8(또는 QKV만 U8)에서는 정수 커널로 계산된다.
- 정수 QKV가 덜 정확한 원인 가설: ① U8×S8 정수 커널의 중간 합 포화 (이 PC는 `avx512_vnni=true`라 ORT가 VNNI 경로를 쓰면 포화가 없어야 한다 → 가능성 낮음, reduce_range 실험으로 확인) ② 출력 재양자화 반올림 방식 차이. 확인 방법: `reduce_range`(7비트 가중치) 또는 `session.x64quantprecision=1`로 QKV U8 모델을 다시 재 본다 (G6 계획 항목, CLAUDE.md 3절).
- 결정에 주는 의미: "S8 정확도 + U8 속도"를 QKV U8로 함께 얻을 수는 없었다. QKV를 float(S8의 우연한 동작)로 두면 정확하지만 4스레드에서 Q/DQ 오버헤드가 크고, 정수로 두면 빠르지만 0.41%p를 잃는다.
