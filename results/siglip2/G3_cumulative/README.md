# G3 누적 구성: 보호하는 fc2 줄이기 — 크기·정확도 곡선 (2026-10-13, 진행 중)

출발점은 보정 방식 비교의 최선(`../G3_calib_method`): Percentile 99.999(비대칭, 16장씩 나눠 누적) + **MatMul만 INT8** + 블록 5~11 fc2 FP32.
여기서 FP32로 남기는 fc2를 줄여 크기를 더 줄인다. 잔차 흐름(Add·LayerNorm)과 GELU는 모든 구성에서 FP32.
스크리닝: dev 6종 각 앞 200장, **정수 커널**, 고화질 cos(주)·Δtop-1(참고) (D-024). 보정 highres 256장 시드 0. 이 PC.

**중간 결론: 블록 5와 9의 fc2 두 개만 FP32로 두면 충분하다 (fc2L2: 고화질 cos 0.956, dev 전체 Δtop-1 −0.50%p [−1.01, +0.01], 105.3 MiB = FP32 대비 −70.3%). 둘 중 하나라도 INT8이면 크게 떨어진다(200장 스크리닝).**

## 실행 명령
```bash
cd siglip2
bash scripts/g3_cumulative.sh screen    # fc2L4, fc2L2 (커밋 63d455f)
bash scripts/g3_cumulative.sh screen2   # fc2L1(블록 5만 / 9만), fc2L2 U8 (커밋 6d2eede)
bash scripts/g3_cumulative.sh full      # 상위 후보 dev 전체 재측정 (진행 중)
bash scripts/g3_cumulative.sh speed     # 지연 (다른 작업이 없을 때)
```

**U8 − S8 (fc2L2) −0.41 [−0.78, −0.02] → U8이 유의하게 나쁨** (L2U8 − L7 −0.45 [−0.85, −0.08], L2U8 − L4 −0.57 [−0.95, −0.20]).

- **200장 스크리닝과 dev 전체의 cos가 0.0002 이내로 같고 순위도 같다** (D-024 스크리닝 방식 확인). top-1은 200장에서 +0.2~+0.6이었으나 전체로는 −0.3~−0.9 → 200장 top-1은 잡음이 크다(주 지표를 cos로 둔 이유).
- S8 세 구성은 서로 동률이다. **PRD 5절 규칙(동률이면 cos로 고른다)으로는 fc2L7(cos 0.9584)이 앞서고, 크기로는 fc2L2(105.3 MiB)가 앞선다.** 최종 선택은 팀이 후보표(크기·지연·정확도)로 한다(CLAUDE.md, PRD 8절). 지연은 아래에서.
- U8은 QKV 투영까지 정수로 실행되지만 정확도가 유의하게 낮다 → 속도 이득이 있는지 확인 후 판단 (지연: `speed/README.md`). (10/14 정정: ORT 최적화 그래프의 노드 이름으로 확인하니, S8에서 정수로 합쳐지지 않는 13개는 attention 행렬곱(QKᵀ·AV)이 아니라 **QKV 투영 MatMul 12개 + 헤드 `attn_pool/kv` 1개**다. QKᵀ·AV는 S8에서도 정수로 돈다. QKV 앞뒤만 U8로 바꾸면 합쳐진다 → `--u8-match` 실험)
