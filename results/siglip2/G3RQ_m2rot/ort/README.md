# M2rot ONNX를 ORT(CPU)에서: 예선 후보 확인 (설계 2026-10-19)

> **용 제안, 준혁 동의 전, 결과 보기 전 고정.** 결과를 본 뒤에는 이 기준을 바꾸지 않는다. **dev만 쓴다 (test 사용 금지).**

## 1. 배경
- 공지상 본선은 "예선 모델을 Hailo로 컴파일"한다. 예선 ONNX도 NPU에서 검증된 M2rot(D-043, Hailo 최종)으로 맞출 수 있는지 사전 측정한다.
- 원칙 (용 10/19): 기존 "R0보다 좋아야 교체"가 아니라 **"CPU에서 크게 나쁘지 않으면 M2rot"**.

## 2. 구성
| 이름 | 만드는 법 |
|---|---|
| **M2rot_ort** (주 구성) | M2rot FP32 ONNX `siglip2_image_fp32_rcmaskbcmlp55at5-13at9_rothad.onnx` (sha256 `16ef696e…`, G3RQ `export.jsonl`)를 `s2_quantize.py --src`로 **MatMul 전부 INT8 (fc2 예외 없음)**, U8 + reduce_range, highres 256장 시드 0, percentile 99.999, hc16. R0와 같은 양자화 옵션 (`--exclude`만 없음) |
| **R0** (비교 기준) | Release ORT 최종 fc2L2 U8+rr, sha256 `5eee7839…` (D-030). 파일은 Release `siglip2-xplat-20261015`의 것 (`~/siglip2_work/xplat/models/`, sha256 확인). x86 VNNI 두 세대에서 출력이 비트 단위로 같아(G3_xplat) 이 PC에서 그대로 돌린다 |
| FP32 | Release `siglip2_image_fp32.onnx` (`333cad08…`) |

## 3. 판정 (예선 후보 조건, 모두 만족)
- **① M2rot_ort − R0 고화질 Δtop-1 95% 구간 하한 ≥ −0.5%p** (dev 전체, `s2_paired_ci.py`, 층화 짝 부트스트랩 시드 0·1000회)
- **② 지연이 FP32보다 느리지 않음** — 측정한 모든 스레드 수(1·2·4)에서, 3세션 중앙값 기준
- 기록만 (판정에 안 씀): 크기·지연·메모리가 R0보다 좋은지, FP32 대비 Δtop-1, 고화질 cos, CIFAR A Δ.
- 둘 다 만족하면 "예선 후보" → 팀(준혁) 결정. 교체 시 최종 test 평가를 다시 해야 한다 (test는 이번에 쓰지 않음).

### a단계 관문 사후 변경 (10/19, **사후 변경, 용 승인** — 결과를 본 뒤)
- 변경: a단계 관문을 "dev 64장 + dev 6×200 모두 ≥ 0.999"에서 **"dev 64장 ≥ 0.999"**로 바꾸고 b단계로 진행한다.
- 이유 (용):
  1. 0.999는 64장 결과만 보고 정한 안전장치 값이라 1200장에는 너무 빡빡했다.
  2. 0.9984는 근사가 깨진 수준이 아니다.
  3. FP32 dev 전체 Δtop-1이 +0.10 [0.00, +0.22]%p로 손실이 없다 (G3R R1 FP32, `../../G3R_regcache/fp32_full`).
  4. 예선 후보 판정 기준 ①②(3절)는 바꾸지 않는다.
- 앞으로 M2 근사 cos 최소는 **0.9994 (dev 64장) / 0.9984 (dev 6×200)** 둘 다 적는다.

### b단계: 양자화 → 스크리닝 — **관문(고화질 cos ≥ 0.99) 미달 → 멈춤** (10/19 08:5x, 커밋 `5413b5f` dirty 아님)
- 양자화 (`int8/quantize_log.jsonl`): M2rot_ort 91.72 MiB, 정수 MatMul **79개 전부 QLinearMatMul**, 보정 실제 장수 256.

| 구성 (dev 6×200, 정수 커널 4스레드, `screen/screen.jsonl`) | 크기 MiB | 정수 MatMul | 고화질 cos | 고화질 Δtop-1 | CIFAR A Δ |

- R0보다 cos +0.021, 크기 −13%이지만, 4절 관문 0.99에 못 미친다 → c단계 이후 하지 않음.
- 원인 가설 (확인 안 함):
  1. **관문 값 자체가 ORT INT8로는 닿은 적 없는 수준이다.** 지금까지 ORT INT8 구성의 최고 스크리닝 cos는 E3(attn proj FP32) 0.9722, rothad_r2 0.9687, R0 0.9545였다. 0.99는 FP32 근사(0.999)나 Hailo 16비트 혼합(M2rot_D256L1 0.9866)에 가까운 값이다.
  2. **남은 손실은 M2rot가 다루지 않는 MatMul의 텐서별 8비트 눈금에서 나온다.** 진단 2(G3Q 10-8)에서 남은 cos 손실의 39%가 attn proj, 21%가 fc1이었다. M2rot는 sink 토큰(fc2 거대 값)과 잔차 채널 쏠림을 다루지만, attn proj 입력·fc1 쪽 손실은 그대로다.
  3. (작은 몫) M2 근사 자체의 손실: FP32 단계에서 cos 최소 0.9984 (dev 6×200), 평균은 0.9999 수준이라 0.0001 안팎.
