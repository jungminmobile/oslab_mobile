### 2-4. 우리 M2rot(D256L1)에 실제로 적용된 상수 캐시 범위 (요청 3, `siglip2/s2_regcache.py`에서 확인)

M2rot = `s2_regcache.py --graph mask --mask-form bcast --mask-site mlp --rot rothad --sinks 55@5,13@9 --calib-n 256 --seed 0` (G3RQ README 11행, `MaskRegCacheTrunk`).

| 항목 | 실제 적용 |
|---|---|
| sink | `(p, b)` = (패치 55, 블록 5), (패치 13, 블록 9). 둘 다 G3_why에서 **그 블록의 MLP(fc2)가 거대 값을 써 넣는 첫 블록**이다 |
| attention K/V | 블록 l ≥ b의 self-attention에서 위치 p의 K(`k_norm` 뒤)·V를 상수로 바꿔 끼운다 (토큰 수 유지, `_replace_kv`). 활성 sink는 블록 l에서 b ≤ l인 것 |
| MAP 헤드 | 풀링 헤드 kv에서 **모든 sink 위치**의 K·V를 상수로 바꾼다 |
| MLP 입력 (M2) | 블록 l ≥ b에서 sink 행의 `norm2` 출력(affine 포함)을 `u_c[l]`로 바꾼다. `u_c[l]` = 원래 모델 블록 l `norm2` 출력의 보정 사진·비-sink 토큰 평균 |
| 잔차 | 건드리지 않는다 (`mask_site=mlp`이면 잔차 마스크 없음) |
| 상수 | 원래 FP32 모델에 보정 256장(highres, 시드 0)을 넣어 블록·헤드별 sink K·V 사진 평균 (`build_mean_cache`), `u_c` (`build_uc`) |
| 회전 | rothad는 FP32에서 수학적으로 같은 변환이라 (G3Q·G3RQ에서 확인) FP32 cos에는 영향이 없다 → 5번은 **회전 없이 M2만** 잰다 |

**새 모델로 옮기는 규칙 (결과 전 고정):**
- sink `(p, b)`: 패치 p가 블록 b 출력에서 high-norm 토큰(토큰 L2 노름 > 중앙값의 5배, G3_why 정의)인 사진이 128장 중 90% 이상이고, b는 그런 첫 블록. 그리고 p가 **어떤 블록 l > b**에서 attention 상위 2개 고정성(4절 기준) ≥ 90%여야 한다. 둘을 모두 만족하는 (p, b)를 모두 sink로 쓴다.
- 이 규칙이 REF에서 정확히 {55@5, 13@9}를 내는지 먼저 확인한다 (6절 기준 모델 검증). 다르게 나오면 REF에서 {55@5, 13@9}를 내도록 고친 규칙을 대상 모델을 보기 전에 커밋한다.
- K/V·MAP 헤드·u_c·보정 256장 처리는 위 표 그대로. HF 구조의 대응: `layer_norm1`→`norm1`, `self_attn.k_proj/v_proj`→`qkv`의 K·V (HF SigLIP에는 q/k norm 없음), `layer_norm2`→`norm2`, `post_layernorm`→`trunk.norm`, `head`(MultiheadAttentionPoolingHead)→`attn_pool`.
- 패치 번호는 위치 임베딩과 같은 행 우선(row-major) 순서다 (패치 55 = 행 3, 열 13 / 14×14).
- **판정에 쓰는 5번 값 = M2 전체 (K/V 상수 + MAP 헤드 + u_c)**. "K/V만 바꾼 것"(u_c 없음)은 기록용으로 같이 잰다.
- 구현 검증: (i) oracle(그 사진의 실제 K·V, u_c 대신 실제 norm2 출력)로 바꾸면 원래와 cos 최소 ≥ 0.99999. (ii) REF에 기존 timm 전처리 캐시와 기존 상수 파일(`regcache_55at5-13at9_highres256_s0.npz`, `regcache_uc_…npz`)을 넣었을 때 내 HF 구현의 출력이 timm `MaskRegCacheTrunk`(bcast, mlp)와 cos 최소 ≥ 0.99999. 실패하면 멈춘다.

## 3. 측정 (요청 1~6)

- 모든 HF 모델은 `attn_implementation="eager"`, FP32, `torch.set_num_threads(6)`, `OMP/MKL/OPENBLAS_NUM_THREADS=6`. 시간 측정 없음.
- **1번 가중치 동일성**: Zoo ONNX(ORT 1.25 `ORT_ENABLE_ALL`, CPU, 출력 `1393`/`1725`) vs HF `vision_model(...).pooler_output`, 2-3의 32장 (Zoo 전처리 캐시). 평균 cos < 0.9999면 **멈추고 보고**.
- **4-1 (요청 4) REF 동일성**: HF `google/siglip2-base-patch16-224` vs 우리 timm FP32(`S.load_model()` `encode_image`, 정규화 전)의 출력 cos, 같은 32장 (기존 timm 전처리 dev 캐시를 두 모델에 똑같이 넣음). 평균 cos < 0.9999면 **멈추고 보고**.
- **2번 구조표**: pre-LN 여부(잔차에 더하기 전 LN을 거치는지), LN 개수, MAP 헤드 유무, CLS 토큰 유무, 위치 임베딩 방식, 블록 수, hidden. 회전을 LN에 접는 우리 방식(`s2_rotate.check_trunk` 조건: 잔차를 읽는 곳이 LN뿐, 더하는 곳이 patch_embed·pos_embed·attn out_proj·fc2뿐)이 맞는지 코드로 확인.
- **3번 거대 활성값** (128장): 블록 출력 잔차 h (토큰 × 768)에서 블록별
  - `max|x|`, `median|x|` (그 블록 128장 전체 원소), **ratio = max|x| / median|x|** ← 판정
  - 상위 5개 채널(채널별 max|x|), 상위 5개 토큰 위치(위치별 max|x|), 기록용으로 G3_why 지표(토큰 노름 max/중앙값, high-norm 토큰 수·위치)
- **4번 sink** (128장): 블록·헤드별 attention 확률을 query 평균해 key 토큰별 질량 (사진마다). MAP 헤드도 같은 방식.
  - **고정성 = 블록 l에서 헤드 평균 질량의 상위 2개 안에 위치 p가 드는 사진 비율** ← 판정. 헤드별 값은 기록용.
  - K/V 일관성: sink 위치 K·V의 사진 평균 대비 cos (블록·헤드별 중앙값) — **기록용만** (요청 반영 1).
- **5번 상수 캐시 FP32**: 2-4 규칙으로 정한 sink에 M2를 적용한 FP32 모델 vs 원래 FP32의 임베딩 cos, dev 6×200 (1,200장). **판정 값 = 1,200장 평균 cos**. 데이터셋별 평균·최소, top-1 변화도 기록.
- **6번 FP32 top-1**: HF 텍스트 인코더(FP32, `padding="max_length", max_length=64`), 템플릿·클래스 이름은 기존 dev와 같은 것(`rn50/common.TEMPLATES`, `rn50/datasets` 템플릿), 앙상블은 `S.zeroshot_classifier`와 같은 방식(문장 정규화 → 평균 → 정규화). dev 6×200 top-1. 30분 안에 안 되면 건너뛰고 이유 기록.

## 4. 판정 (결과 전 고정)

| 항목 | 규칙 |
|---|---|
| 회전 적용 | 2번에서 pre-LN이고 LN 접기가 가능하면 **가능** |
| 거대 활성값 | 어느 블록이든 ratio ≥ 100이면 **있음**, 모든 블록 ≤ 20이면 **없음**, 그 사이 **약함** |
| sink 적용 | 2-4 규칙으로 sink가 1개 이상 나오고(고정성 ≥ 90%), 5번 M2 cos 평균 ≥ 0.999이면 **가능**. 하나라도 실패하면 **불가**로 두고 어느 조건에서 실패했는지 적는다. K/V cos(평균 대비)는 판정에 쓰지 않는다 |
| 결론 한 줄 | 회전 가능 & sink 가능 → **M2rot 전체 적용** / 회전 가능 & sink 불가 & 거대 활성값 있음·약함 → **회전만 적용** / 거대 활성값 없음 → **적용 이점 없음** (회전·sink 모두 거대 활성값 대책이므로) |

**기존 기준을 쓰지 않은 이유**: G3_why(high-norm = 노름 > 중앙값 5배)는 2-4의 sink 찾기 규칙에 그대로 썼다. RegCache G0의 K/V cos 0.95는 기록용이었고, REF도 블록 9 V가 0.39인데 M2rot이 작동하므로 판정에서 뺐다 (요청 반영 1). G1b의 FP32 cos ≥ 0.99는 요청한 0.999보다 느슨해서 요청 값을 쓴다.

## 5. 기준 모델 검증 규칙 (요청 반영 2, 결과 전 고정)

1. **REF를 먼저 잰다** (3·4·5번, 2-4 sink 규칙 확인). 대상 모델(B32·S1B16)의 3~5번 결과는 그 전에 보지 않는다. 1번 동일성 확인은 가중치 확인이라 먼저 해도 된다.
2. REF가 통과하지 못하는 문턱은 **REF 값으로 바꾼다**:
   - 거대 활성값 "있음" 문턱: REF 최대 ratio < 100이면 → REF 최대 ratio (소수 첫째 자리 내림)로
   - sink 고정성 문턱: REF의 55@5·13@9가 90% 미만이면 → 둘 중 낮은 값으로
   - 상수 캐시 cos 문턱: REF M2 cos 평균 < 0.999이면 → REF 값 (소수 넷째 자리 내림)으로
   - sink 찾기 규칙이 REF에서 {55@5, 13@9}를 정확히 내지 않으면 → 2-4대로 규칙을 고친다
3. 바꾼 값과 이유를 6절에 적고 **대상 모델을 측정하기 전에 커밋**한다. 바꿀 것이 없어도 "바꾸지 않음"을 커밋한다.

## 6. 기준 모델(REF) 결과와 문턱 조정 (대상 모델 3~5번 측정 전에 커밋)

먼저 잰 것: 1번·4-1 동일성 (`ident.jsonl`), REF analyze (`analyze.jsonl` 2번째 줄, 커밋 `237c619`), m2xchk, REF m2 (`m2.jsonl`).
대상 모델(B32·S1B16)은 이 시점까지 `ident`(가중치 동일성)만 돌렸고 3~5번은 돌리지 않았다.

| 항목 | REF 값 | 문턱 | 조정 |
|---|---|---|---|
| 거대 활성값 ratio 최대 | **1243.5** (블록 9) | ≥ 100 | 통과 → **바꾸지 않음** |
| sink 고정성 55@5 / 13@9 | 1.00 / 1.00 (헤드별) | ≥ 0.90 | 통과 → **바꾸지 않음** |
| M2 FP32 cos 평균 (1,200장) | **0.99983** | ≥ 0.999 | 통과 → **바꾸지 않음** |
| sink 찾기 규칙이 {55@5, 13@9}를 내는가 | 처음 규칙: **{55@5}만** | — | **규칙 고침 (아래 1)** |
| 구현 대조 m2xchk (HF M2 vs timm M2 cos 최소 ≥ 0.99999) | 0.999972 | — | **사후 변경 (아래 2)** |

1. **sink 찾기 규칙 조정 (5절 2번 규칙에 따름):** 패치 13은 블록 9~11 출력에서 128장 모두 high-norm이지만, 블록 10·11에서 **헤드 평균** attention 상위 2개에는 거의 들지 않는다 (최대 3.9%). 그 자리는 55와 1이 차지한다. 대신 **블록 11 헤드 6**에서 128장 모두 상위 2개에 든다 (질량 0.062, 균등 분배 0.0051의 12배).
   → 2-4의 attention 조건을 "**블록 l > b의 어느 한 헤드에서든** 상위 2개 고정성 ≥ 90%"로 바꾼다. 4절 sink 판정의 "고정성"도 같은 정의(헤드별 최대)를 쓴다. 헤드 평균 고정성은 기록용으로 함께 적는다.
   (5절 2번은 "고정성 문턱을 REF 값(13의 헤드 평균 최대 0.039)으로 낮추기"로 읽을 수도 있다. 사후 검토에서 두 방식의 판정이 같음을 확인했다: B32 7@9 헤드 평균 최대 0.188 ≥ 0.039이고, S1B16은 어느 쪽이든 high-norm 조건에서 실패한다.)
   바꾼 규칙의 REF 결과는 정확히 **{55@5, 13@9}** (패치 1은 high-norm 비율이 최대 83.6%라 빠지고, 41·153·167·28은 high-norm이 아니라서 빠진다).
2. **구현 대조 문턱 사후 변경 (판정 문턱이 아닌 구현 검증):** 같은 상수 파일·같은 64장(timm 전처리)을 넣었을 때 HF M2와 timm M2의 cos 최소는 0.999972였다. 그런데 **원래 모델끼리도** HF와 timm의 cos 최소가 0.999978이다 (GELU·attention 구현의 수치 차이). 그래서 2-4의 "≥ 0.99999"는 구현과 상관없이 넘을 수 없는 문턱이었다. 다음 두 가지로 바꿔 확인했고 둘 다 통과했다.
   - HF M2 vs timm M2 cos 최소 ≥ (원래 모델끼리 cos 최소 − 1e-5)
   - M2가 바꾼 양 (1 − cos(M2, 원래), 64장 평균): timm 9.206e-5, HF 9.197e-5 (상대 차이 0.09%)
   - 내 상수 계산(`build_m2_consts`, 같은 timm 전처리 보정 256장)과 기존 파일의 최대 차이: K 0.0046, V 0.0039, u_c 0.052. 이것도 원래 모델의 수치 차이 범위다. oracle 동치(cos 최소 1.0000000)는 치환 위치·인덱스만 확인한다. `_oracle_forward`는 따로 쓴 경로라 `hf_forward`의 상수 치환(`_replace`)·u_c 경로는 거치지 않는다. 그래서 **M2 경로 자체의 검증은 이 m2xchk(REF만)이다.** 이것도 완화한 문턱(0.9999677)을 작은 차이(cos 최소 0.9999716)로 넘었다. 대신 M2가 바꾼 양은 0.09%까지 맞는다.
3. **M2 = K/V만:** FP32에서 M2(u_c 포함)와 K/V만 바꾼 결과가 비트 단위로 같았다 (1,200장 모두). MLP는 토큰별 연산이라 sink 행의 출력이 다른 토큰에 닿는 길은 K/V뿐인데, 그 K/V를 이미 상수로 바꿨기 때문이다. u_c는 양자화(sink 행의 거대 값이 MLP 눈금을 정하는 것)를 막기 위한 장치라 FP32 cos에는 나타나지 않는다. 판정은 그대로 M2 값으로 한다.

REF 상세 값은 7절 표에 대상 모델과 나란히 적는다.

- 각 200장이라 1장 = 0.5%p다. M2 줄의 변화는 신뢰구간 없이 본 값이다 (짝 부트스트랩 안 함).
- 텍스트 분류기: HF 텍스트 인코더 FP32, 템플릿·클래스 이름은 기존 dev와 같다. 문장은 open_clip `_clean_canonicalize`(소문자·구두점 제거)로 정리한 뒤 max_length 64. 확인: 이렇게 만든 REF 분류기는 기존 timm 분류기(`*_clf.npy`)와 6종 모두 cos 1.0000이다.
- Zoo 공식값(CIFAR-100 test, float: B32 74.66, S1B16 72.28)과는 데이터·프롬프트가 달라서 직접 비교하지 않는다.

## 8. 계획과 달라진 점·기록

1. **sink 찾기 규칙** (6절 1): REF에서 13@9가 헤드 평균 attention 상위 2에 들지 않아 헤드별 최대로 바꿨다 (대상 모델 측정 전에 커밋 `eee84e0`).
2. **구현 대조 문턱** (6절 2): 원래 모델끼리도 못 넘는 문턱이라 사후에 바꿨다 (판정 문턱 아님).
3. **top-1 첫 실행 철회**: 처음 top1(`top1.jsonl` 1·2번째 줄, 커밋 `eee84e0`)은 문장 정리 없이 HF 토크나이저에 넣어서 Cars가 3.5%·2.0%로 무너졌다 (대문자가 많은 클래스 이름 — SigLIP 계열은 소문자·구두점 제거 텍스트로 학습). 이 두 줄은 **쓰지 않는다.** open_clip과 같은 정리(커밋 `e2117fb`)로 다시 쟀다.
4. **sentencepiece**: S1B16 토크나이저(`SiglipTokenizer`)에 필요한데 공용 venv에 없었다. 공용 venv는 바꾸지 않고 `~/siglip2_work/g6pre/pylib`에 `uv pip install --target`으로 넣어 `PYTHONPATH`로 이 실행에만 썼다 (sentencepiece 0.2.2).
5. B32 진단 3개(7-5)는 계획에 없던 기록용 실행이다. `~/siglip2_work/g6pre/emb_b32_*_m2.npy`와 `m2consts_*`는 마지막 실행(15@6,7@9) 값으로 덮였다. top-1의 B32 + M2 줄은 그 전에 15@5,7@9로 잰 값이다.
6. 보정 사진 대조: 다시 만든 256장을 timm 전처리하면 기존 `calib_images("highres",256,0)`와 최대 차이 0 (같은 사진·같은 순서). dev 5종은 SHA-1 목록이 기존 캐시와 일치, CIFAR A 정답 일치.
7. 확인 못 함: HF 모델에 회전을 실제 적용한 동치 확인, S1B16의 풀린 LN이 DFC에서 다시 묶이는지, Zoo `.alls`의 `normalization`과 `clip.yaml` `normalization_params`가 겹쳐 적용되지 않는지(DFC 미사용; G5c 해석을 따름), 짝 부트스트랩 신뢰구간.

## 9. 결론과 다음 결정 (팀)

- **B32 (siglip2_b_32_256): 회전만 적용** (판정). REF와 기전이 같다: 같은 채널 67·301·145·483, 같은 블록 5·9, 위치가 고정된 sink 15·7. 실패한 것은 "시작 블록에서 K/V를 상수로 바꾸는 것" 하나이고, 시작 블록을 한 칸 미루면 REF 수준(0.99981)이 된다.
  → 주의: 15@6은 dev에서 찾은 변형이다. 채택한다면 결과 전에 규칙을 고정하고 다른 사진(보정 시드 또는 dev 나머지 800장)으로 다시 확인해야 한다. M2 상수는 보정 시드 1개이고 신뢰구간이 없다. B32 최소 cos 0.9525는 Cars 사진 1장이다.
  → **팀 결정:** 규칙을 "K/V 상수는 b+1부터, u_c는 b부터"로 바꾼 M2 변형을 B32에 정식 판정 대상으로 넣을지. 넣는다면 REF에서도 같은 변형을 다시 재서(REF는 원래 규칙으로 통과했으므로 비교용) 결과 전에 규칙을 고정해야 한다.
- **S1B16 (siglip_b_16): 회전만 적용** (판정). 거대 활성값은 있지만(1035) 위치가 사진마다 다르다(최대 68%). 고정 위치 상수 캐시라는 우리 sink 방식의 전제가 성립하지 않는다.
- 이후 HEF 비교의 FP32 기준값: 고화질 5종 평균 REF 90.9 / B32 88.9 / S1B16 90.5 (dev 6×200, Zoo 전처리 캐시 `~/siglip2_work/g6pre/cache_zoo{224,256}`).
