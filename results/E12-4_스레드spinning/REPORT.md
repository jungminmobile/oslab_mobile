   - 재발을 막으려고 자식 프로세스에서 Windows 전원 절약(EcoQoS, ProcessPowerThrottling)을 끄도록 했습니다. 이 확인용 실행에서는 API 인자 타입 문제로 끄기가 실패했으나(`throttle_off: false`), 이후 고쳐서 본 측정에서는 적용됐습니다.

## 관찰

- **spinning은 이 모델에서 지연을 줄이는 쪽으로 작동합니다.** 끄면(A1) 4T가 10.8% 느려지는 대신 CPU가 30% 줄어듭니다. E12-3에서 본 "작은 연산의 스레드 대기 비용"은 spinning이 이미 줄이고 있는 비용이라는 뜻입니다. spinning을 끄면 그 비용이 그대로 드러납니다.
- **dynamic_block_base 4는 오히려 해롭습니다** (+25.8%). 작은 연산을 더 잘게 나누면서 나눠 주기 비용이 늘어난 것으로 보입니다.
- **A4(force_spinning_stop)의 CPU 절감은 전부 Run 뒤 꼬리에서 나옵니다.** 루프만 보면 A0와 같고(65.39 vs 65.23 ms/장), 꼬리는 0.97 s → 0입니다. 연달아 처리할 때는 −6%지만, 한 장씩 간격을 두고 처리하는 실제 사용에서는 더 클 수 있습니다. 이 실험의 측정 범위는 아닙니다.
- **3스레드는 4스레드보다 느립니다** (A0 18.26 vs 16.38 ms). "4T 예산에서 3스레드가 더 빠르다"는 관찰은 없습니다.
- **CPU 사용량**: A0 4T는 루프 동안 장당 CPU 65 ms / 벽시계 16.4 ms ≈ 4코어를 다 씁니다(spinning). A1은 약 3코어입니다.
