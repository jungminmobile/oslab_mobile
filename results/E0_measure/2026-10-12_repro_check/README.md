# E0 출발점: 재현 확인 (2026-10-12)

E0 코드 수정을 하기 **전에**, 정리된 저장소 코드(`rn50/`, 커밋 `a1fb3ef` 기준)가 10/7 결과를 그대로 재현하는지 확인했다.
이 값은 E0 이후 `smoke_test.py`의 기준값으로 쓴다(옵션을 모두 끄면 이 숫자가 나와야 한다).

## 결론

1. 정리된 저장소 코드는 10/7 결과를 **완전히 재현**한다.
2. Windows 노트북에서도 같은 정확도가 나온다(FP32 동일, c3 ±1장).
3. q1(AttnPool 최적화)만으로 4~8% 빨라진다. 보고서에서 "원본 → q1 → q1+INT8"로 따로 보고할 근거다.
4. 노트북 1스레드는 흔들림이 크다(성능·저전력 코어 혼재 추정). 주 측정 조건은 4스레드가 맞다.
5. **클라우드 절대 속도는 세션마다 다르다.** 10/7 클라우드(Xeon 2.10GHz)는 c3 33.4ms, 오늘(Xeon 2.80GHz) 39.8ms였다. 속도는 같은 측정 안의 비율로만 비교하고, 보고 절대값은 노트북에서 잰다.

## E0 수정 목록에 추가할 것

- `export_onnx.py --verify`와 `bench_speed.py`는 CIFAR-100 원본(`rn50/data/`)이 필요하다. 없으면 오류로 멈추는데 README에 안내가 없다.
- CIFAR-100 공식 서버가 느리다(노트북에서 약 65KB/s, 169MB에 약 40분). README에 미리 알린다.
- `bench_speed.py`의 CPU 기록이 부정확하다. 클라우드는 `x86_64`, Windows는 `Intel64 Family 6 Model 189`로만 남는다(PRD B11).
