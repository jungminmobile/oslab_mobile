## 1. 왜 하는가

- O의 GELU(tanh 근사)는 13곳 모두 원소별 연산 9개로 쪼개져 있다 → 117노드. 작은 원소별 연산은 4T에서 스레드 효율이 낮다(E12-3: Add·Mul·Sub 묶음 21.1%, 효율 0.29).
- GELU는 fc1 출력(float)과 fc2 입력 QuantizeLinear 사이의 **float 구간**에 있다 → Q/DQ 값이 안 바뀐다 → 재양자화 없이 **O와 바로 비교**.
- 이 실험만으로 제출 모델을 바꾸지 않는다. 채택 후보여도 **팀 결정 D-050** 뒤에 E14 결과를 모아 정한다.

## 2. 바꿀 곳 (그래프 직접 확인, 10/23)

```
fc1 MatMul(DQ, DQ) → fc1/Add(bias) → [Mul(x·x) → Mul(·x) → Mul(·0.044715) → Add(x+…) → Mul(·√(2/π)) → Tanh → Add(1+…) → Mul(x·…) → Mul(·0.5)] → QuantizeLinear(fc2 입력)
                                       └─────────────────────────── GELU 9노드 ───────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 곳 수 | 13 (블록 0~11 MLP + MAP 헤드 MLP), **13곳 모두 같은 구조** (리뷰 사전 확인) |
| GELU 노드 | 9 × 13 = 117 |
| bias Add | 13 |
| ORT가 이미 합치는가 | **아니다.** 최적화 후에도 Tanh 13개·Mul·Add 그대로 (CPU에서는 GELU 융합이 안 일어남) |
| ORT가 fc1 bias를 MatMulIntegerToFloat에 합치는가 | **아니다.** 66개 모두 bias 입력 없음, bias Add가 따로 남음 |
| ORT CPU FastGelu 커널 | 있음. `FastGelu(x)`·`FastGelu(x, bias)` 모두 동작. 시험 입력에서 원래 식과 max\|Δ\|/max\|y\| = 6.6e-8, 원소 86%는 비트 일치 |

## 3. 바꾸는 방식

| ID | 바꾸는 범위 | 결과 | 노드 (13곳 합) |
|---|---|---|---|
| O (기준) | — | bias Add + GELU 9노드 | 130 |
| **F1** | GELU 9노드만 | `FastGelu(x)` (bias Add 그대로) | 26 |
| **F2** | bias Add + GELU 9노드 | `FastGelu(x, bias)` | 13 |

**기대 4T: −3~4% (보수적 추정)**
- E14-1 교훈: 노드를 없앤 만큼 빨라지지 않는다 (W1 노드당 약 8.5 µs, W2 약 2 µs). FastGelu도 tanh는 계산해야 한다.
- 다만 E14-1은 작은 텐서(64×12×64), GELU는 64×3072로 약 4배 커서 노드당 절감이 더 클 수 있다.

**수치**
- FastGelu 식 `0.5·x·(1 + tanh(√(2/π)·(x + 0.044715·x³)))`은 원래 식과 같다. 하지만 커널의 tanh 계산이 달라 **비트 단위로 같지 않을 수 있다** → 뒤의 QuantizeLinear에서 드물게 정수 1 차이.

**바꾸는 규칙**
1. 13곳 모두 상수(0.044715, √(2/π), 1, 0.5)와 연결 구조를 검사한다. 다른 곳은 바꾸지 않고 기록한다.
2. F2는 x(bias Add 출력)를 GELU 말고 다른 곳에서 쓰지 않을 때만 bias를 흡수한다.
3. Q/DQ 노드와 그 상수, 다른 연산은 건드리지 않는다.

## 4. 관문 (불통과면 멈추고 정민에게 보고)

| 관문 | 확인 내용 |
|---|---|
| **G0 재료** | O sha 일치. `Tanh` 13개, 13곳 패턴·상수 일치 (다른 곳은 제외·기록. 13곳 모두 다르면 멈춤) |
| **G1 그래프** | ① F1·F2: `Tanh` 0개, `FastGelu` 13개 (제외만큼 차감) ② Q/DQ 노드 수와 **모든 Q/DQ 상수 sha가 O와 같다** ③ 바꾼 노드 출력 shape이 원래와 같다 ④ ORT 세션 생성 성공, 최적화 그래프 저장 ⑤ **ORT 최적화 후 MatMulIntegerToFloat·QLinear\*·Q·DQ 수가 O와 같다** (F1·F2 모두) |
| **G2 수치** | (a) dev 6×200에서 O 대비 **임베딩 cos 최소 ≥ 0.9999**, top-1 일치율 (`ORT_ENABLE_ALL`, 제출과 같음) (b) 2장, `ORT_DISABLE_ALL`: 곳마다 **F의 FastGelu 출력 vs 같은 입력 x에 원래 GELU 식(numpy, float32, 같은 연산 순서)** → **max\|Δ\| / max\|y\| ≤ 1e-5**. 원소별 상대 오차는 참고로만 (c) 같은 자리 QuantizeLinear 출력(정수)이 O와 다른 원소 비율 기록 (`ORT_DISABLE_ALL`) |
| **G2b 정확도** | dev 6×200에서 top-1이 **하나라도** 다르면 dev 전체(고화질 4,923 + CIFAR A 1,000)로 재고 O 대비 CI |

**G2(b) 비교 방식 (확정본에서 명확화)**: O와 F를 같은 자리에서 바로 비교하면, 앞쪽 곳에서 생긴 정수 1 차이가 뒤쪽 곳의 입력을 바꿔 섞인다(E14-1 G2(c) 교훈). 그래서 (b)는 **곳마다 F 자신의 입력 x 기준**으로 FastGelu 차이만 잰다. O vs F 직접 차이(첫 곳은 섞임 없음)는 참고로 함께 기록한다. (c)는 O vs F 직접 비교라 뒤쪽 곳일수록 누적값이다.

**고르는 법**
- 둘 다 채택 후보 → 4T p50이 낮은 쪽. 차이 1% 이내면 노드가 적은 F2.

**기준 −2% 근거**: 기대치 −3~4%의 절반. 판정은 3세션 중앙값이다. E14-1에서 중앙값은 안정적이었지만 세션 하나는 크게 튀었다(세션 1 O 4T −5.8%, 1T ±4%). 중앙값이면 그 정도는 걸러진다. E14-1(−1.5%)보다 엄격하고 E12(−3%)보다 느슨하다.
