## 1. 배경: 왜 다시 하나

| 문제 (10/6~7 코드 검토) | 영향 | 조치 |
|---|---|---|
| ORT 1.25 `CalibMaxIntermediateOutputs` 버그 → 보정 사진 256장 중 마지막 16장만 사용 | 지금까지의 **모든 INT8 결과 무효** (방향성 참고용) | 옵션 삭제, 256장 전부 사용 |
| 고화질 데이터셋 설정 비교에 test 사진 사용 | 최종 점수가 부풀려질 위험 | dev(train 분할)로 비교, test는 마지막 1회 |

## 2. 실험 규칙 (프로토콜)

### 2-1. 데이터 구간

| 용도 | 데이터 | 비고 |
|---|---|---|
| 보정 (눈금 정하기) | CIFAR train[0:45000] 또는 고화질 5종 train 중 dev가 아닌 사진 | test 사진은 절대 사용 안 함 |
| 설정 비교 (dev) | CIFAR train[45000:46000](A)·[46000:47000](B), 고화질 5종 train 분할에서 해시 선택 약 1000장씩 | Pets, Flowers, Cars, Food, Caltech |
| 최종 점수 (test) | 각 데이터셋 test 전체 + ImageNetV2 | **이번 실험에서는 하지 않음.** 최종 모델 결정 후 1회 |

### 2-2. 실행 방식

| 측정 | 방식 |
|---|---|
| 설정 비교용 정확도 (C단계) | 정수 커널 (`evaluate.py --exec int`). 이 서버는 AVX512-VNNI가 있어 포화 없음, 순위 비교용 |
| 상위 후보 확인 (F단계)·최종 점수 | fake-quant (`--exec fake`). CPU 종류와 무관하게 재현 |
| 속도 | 정수 커널, `bench_speed.py` (같은 측정 안에서 번갈아 3회 반복) |

### 2-3. 지표

- **top-1 / top-5** 제로샷 정확도 (%), FP32 대비 변화 (%p)
- **cos_mean**: FP32 원본과의 평균 코사인 유사도. 층 보호 여부를 고르는 주 지표 (정답 불필요, 흔들림 작음)
- **용량** (MiB, FP32 대비 감소 %), **속도** (장당 ms, FP32 대비 %)
- 1000장 기준 top-1 흔들림 약 ±1.5%p → 이보다 작은 차이는 결론에 쓰지 않음

### 2-4. 양자화 기본 설정

- ONNX Runtime 1.25 정적 PTQ, QDQ 형식, MinMax, 보정 256장(시드 0, 섞음)
- 가중치 INT8 대칭·채널별, 활성값 UINT8 비대칭·텐서별
- 그래프: AttnPool 최적화본(`_q1`, 0번 칸만 query, 출력 동일)
- AttnPool은 항상 "D 방식": q·k·v·c_proj 투영만 INT8, attention 계산(점수·softmax·가중합)은 FP32
- 기본 보정 출처: **highres**(고화질 5종 train). 비교용으로 cifar, mix

### 2-5. 파일 이름 규칙

`rn50[x4]_image_int8_q1_minmax_<출처><장수>_s<시드>_<구성>.onnx`
예: `rn50_image_int8_q1_minmax_highres256_s0_c4.onnx`

구성 이름: `only-<단계>`(단계 하나만), `c1~c5`(누적), `Fon`(전부), `stem+<단계>`, `sc_<조합>`(stem 내부), `w4-<범위>`(4비트)

### 8-2. 결론

1. **보정 버그 수정 후 결론이 바뀜.** 예전 "stem INT8이 CIFAR 정확도를 3%p 올린다"는 16장 보정의 부산물이었음. 고친 보정에서는 사라짐.
2. **RN50 균형점은 c3~c4.** c3: 용량 −72%, 시간 −39%, 손실 −0.7%p. c4: 시간 −53%, 손실 −1.4~−1.6%p. layer1·stem까지 INT8로 바꾸면 손실이 커짐(−2.5~−3.1%p).
3. **보정 출처보다 '튀는 값 처리'가 문제.** CIFAR로 보정한 모델이 고화질에서도 유사도가 더 높음(MinMax가 튀는 값에 끌림). → 다음 단계: percentile/entropy 보정.
4. **RN50x4 INT8이 RN50 FP32보다 정확하고 작음.** 예: RN50x4 c5(85 MiB)가 RN50 FP32(146 MiB)보다 Cars +10%p, Food +8%p. 대신 CPU에서 1.3배 느림(70 vs 54.5 ms). Hailo-10H에서의 실제 속도 비교가 결정 요인.
5. **4비트는 단순 방법으로는 불가.** 잘라내기로 일부 개선(AttnPool만: −3.5%p). AdaRound·Hailo DFC 4비트 기능 필요. 4비트는 CPU에서 오히려 느림.
6. **정수 커널 vs fake-quant 순위 일치** → 빠른 정수 커널로 설정을 고르고, 최종 점수만 fake-quant로 재는 방식이 타당.
7. CIFAR-100은 stem 변화에 과민해서 설정 선택 지표로 부적합. 고화질 dev 평균과 유사도를 주 지표로 쓰고, CIFAR는 Hailo 공식 수치 비교용으로만 사용.
