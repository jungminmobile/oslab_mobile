# 실험 유의사항 (정민 노트북·클라우드·Hailo, 2026-10-12 ~ 10-19 누적)

실험하면서 실제로 겪은 문제와 지켜야 할 규칙을 모은다. 새 실험 전에 한 번 읽는다. 각 항목에 "무슨 일이 있었나 → 규칙"을 적는다.

## 1. 측정·비교 규칙

| # | 있었던 일 | 규칙 |
|---|---|---|
| 1-1 | 노트북 절대 지연이 날마다 최대 1.8배 달랐다 (SigLIP2 FP32 1T: 10/18 305 ms, 10/19 549 ms. 부하 9~19%, 충전 중, 같은 전원 모드). 10/17 오후에는 CPU가 2.2GHz로 묶여 1.4~1.8배 느렸다 | 지연은 **같은 실행 안에서 모델을 번갈아 재고 FP32 대비 배율·감소율**로 비교한다. 다른 날 잰 ms끼리 직접 비교하지 않는다. 보고서 절대값은 한 번의 깨끗한 측정으로 고정하고 날짜를 적는다 |
| 1-2 | 배터리 모드 / 충전 중 / 백그라운드 앱에 따라 절대값이 최대 2.5배 흔들렸다. 같은 실행 안 배율은 4% 안에서 안정 | 공식 측정: 충전 중, SAMSUNG MODE(같은 전원 모드), 다른 앱 종료, 세션 전 CPU 부하 기록 (`Get-Counter '\Processor(_Total)\% Processor Time'`) |
| 1-3 | 같은 모델·같은 사진이라도 정수 커널 정확도가 CPU마다 다르다 (RN50 B2: Xeon AVX512 −1.05 vs 노트북 −1.43, SigLIP2 U8+rr: 준혁 PC −0.78 vs 노트북 −0.62) | **공식 정확도 측정 기기를 하나로 고정**한다. 방법끼리 비교할 때는 같은 기기에서 둘 다 다시 만들고 짝 비교한다 |
| 1-4 | fake-quant 평가가 정수 커널 붕괴를 가렸다 (C2: fake 36.8 vs int 25.5) | 정확도는 **정수 커널(`--exec int`)로만** 잰다 |
| 1-5 | 시드만 바꿔도 RN50 c3 정확도가 0.6%p 흔들렸다 (E3) | 결론은 짝 부트스트랩 95% 구간으로 낸다. 구간에 0이 있으면 "차이 없음". 최종 후보는 시드 0·1·2 평균도 보고 |
| 1-6 | cos는 오르는데 top-1·CIFAR는 그대로이거나 떨어졌다 (E5a RN50 B0: cos 0.928→0.941, top-1 −0.7) | cos는 보조 지표. 채택 판단은 top-1 짝 비교로 한다 |
| 1-7 | x86에서 S8 활성값은 FP32보다 느렸다 (노트북 4T 0.76배) | ORT 기본 활성값은 **U8**. S8은 비교용으로만 |

## 2. 재현성 (파일 지문 sha256)

| # | 있었던 일 | 규칙 |
|---|---|---|
| 2-1 | 같은 ORT 양자화 명령을 다른 CPU에서 돌리면 sha가 다르다 (SigLIP2 fc2L2: 5eee… vs 클라우드 8f47…). 사진별 정답은 같았다 | 제출·측정 모델은 **Release에 올린 파일 하나로 고정**하고 sha256 전체로 확인한다. 다른 기기에서 다시 양자화하지 않는다 |
| 2-2 | Hailo DFC optimize도 기기마다 결과가 다르다 (HAR 84e9… vs b977…, 사진별 cos 차이 최대 0.041, 예측 일치 97%). 둘 다 CPU라 GPU 탓은 아님. top-1·HEF 크기·컨텍스트 수는 같았다 | 본선 HEF는 한 번 만든 파일로 고정. 재현 기준은 "지표(top-1, cos, 컨텍스트) 허용 범위"로 쓴다 |
| 2-3 | 복사·분할 전송 후 파일이 깨질 수 있다 | 복사본마다 sha256을 다시 확인한다 |

## 3. 경로·인코딩 (Windows 노트북)

| # | 있었던 일 | 규칙 |
|---|---|---|
| 3-1 | ORT 형태 추론(`quant_pre_process`, `quantize_static`)이 한글 경로 파일을 못 찾는다 (`..._pre-inferred.onnx` 없음 오류) | 양자화 산출물은 **영문 경로**에 둔다 (`C:\s2art`, `D:\siglip2_xcheck`). rn50/quantize_onnx.py는 영문 임시 폴더를 써서 괜찮다 |
| 3-2 | bat 파일 안에 한글 경로를 직접 쓰면 "파일 이름 구문이 올바르지 않습니다"로 시작도 못 한다 | bat에는 한글을 쓰지 않는다. `%~dp0` 상대경로나 `for /d %%d in ("C:\study\3\2\2026*")`로 경로를 만든다 |
| 3-3 | BOM 없는 UTF-8 .ps1을 PowerShell 5가 CP949로 읽어 한글 주석이 다음 줄을 삼켰다 | .ps1은 BOM 있는 UTF-8로 저장하거나, 복잡한 일은 Python 스크립트로 한다 |
| 3-4 | Desktop Commander로 띄운 자식 프로세스가 중간에 죽었다 | 오래 걸리는 작업은 `Invoke-CimMethod Win32_Process Create`로 띄우고 로그 파일로 확인한다 |

## 4. 환경·데이터

| # | 있었던 일 | 규칙 |
|---|---|---|
| 4-1 | **클라우드 작업 공간이 10/18 초기화되어** E2~E4 원본(evaluate.jsonl, bootstrap.jsonl, pred npz)과 클라우드 캐시·모델이 사라졌다. 요약 md·표는 남아 있다 | 클라우드 결과는 끝나는 즉시 노트북이나 프로젝트로 옮긴다. **E2~E4 숫자를 다시 계산하려면 재실행 필요** (원본 없음) |
| 4-2 | 노트북에서 HF 다운로드가 자주 끊겼다 (WinError 10054, `CRYPT_E_REVOCATION_OFFLINE`) | `rn50/fetch_highres.py`(curl 이어받기·재시도, `--ssl-no-revoke`: 폐기 확인만 건너뛰고 TLS 검증은 유지)로 미리 받는다. 이미 받은 모델은 `HF_HUB_OFFLINE=1` |
| 4-3 | urllib가 끊긴 다운로드를 반쯤 받은 파일로 남겨 다음 실행이 그 파일을 썼다 | parquet은 pyarrow로 열어 보고, 깨졌으면 지우고 다시 받는다 (fetch_highres.py가 함) |
| 4-4 | 클라우드 8GB에서 SigLIP2 percentile 보정이 OOM | 보정 대상 텐서만 저장하고 ORT 메모리 아레나를 끄는 래퍼 사용 (결과는 같음) |
| 4-5 | py-cpuinfo 9.0이 258V의 AVX-VNNI를 false로 찍는다 (사양상 지원) | VNNI 여부는 rn50 `common.run_meta()` 값과 함께 적는다 |
| 4-6 | 노트북으로 파일 보낼 때 한 파일 30MB, 한 번에 100MB 제한 | 큰 파일은 GitHub Release + `gh release download`로 받는다 |
| 4-7 | `s2_model_stats.py`는 시작할 때 PyTorch 모델(HF 가중치)을 불러온다 | peak 메모리만 필요하면 rn50 `bench_mem.py` 방식을 쓰거나 팀과 방법을 정한다 |

## 5. 작업 규칙 (팀 합의)

- 실행 전에 계획·예상 시간을 먼저 말하고, 오래 걸리면 25%마다 진행 보고.
- `rn50\`·`rn50\.venv`는 다른 실험에서 수정·설치 금지. SigLIP2는 레포 밖 `s2_venv` 사용 (siglip2/requirements.txt 그대로).
- 다른 브랜치 실험은 별도 worktree(`..\oslab_s2`, `..\oslab_xcheck`)에서. 작업 브랜치를 바꾸지 않는다.
- "커밋해줘" = 로컬 커밋만. push는 목록을 보여 주고 확인받은 뒤.
- 결과에는 실행한 것만 적는다. 추정치를 결과처럼 쓰지 않는다.
