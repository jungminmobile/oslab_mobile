검토 대상: `rn50_baseline/baseline_rn50.py`, `rn50_quant/` 전체(파이썬 11개, 셸 3개, 총 약 1,400줄)
정리본: 이 폴더(`rn50_clean/`). 정리본으로 다시 만든 모델·결과가 기존 코드와 같은지 확인했어요(아래 "검증").

## 1. 결론부터

- **지금까지 보고한 실험 결과를 뒤집는 오류는 없었어요.**
- 다만 **결과 해석에 영향을 줄 수 있는 허점 1개**(보정 데이터)와, **보고서 숫자 하나를 바꿔야 하는 문제 1개**(초기 속도표)가 있었어요.
- 나머지는 재현성·안전장치 문제라 정리본에서 고쳤어요.

## 3. 문제없음을 확인한 부분

- **데이터 누수 없음**: 보정은 CIFAR train[0:45000], 검증은 [45000:47000], test는 FP32 베이스라인에만 사용.
- **분류기**: 항상 FP32 글 인코더로 만들어 "사진 인코더만" 비교하는 구조가 일관됨.
- **전처리**: 모든 스크립트가 같은 CLIP 전처리(224, bicubic, center crop, OpenAI mean/std) 사용.
- **AttnPool 최적화(q1)**: 원본과 출력 최대 차이 6e-7, 예측 100% 일치.
- **고화질 데이터셋 베이스라인**: Flowers 65.88%, Cars 54.55%로 CLIP 논문(65.9%, 55.3%)과 일치 → 클래스 이름·프롬프트·전처리가 맞음.
- **노드 선택 규칙**: 정리본으로 다시 고른 노드 수가 기존과 같음(④ 104/201, 실험 D 136/201).

# 2차 검토: 외부 지적 5건 검증 (2026-10-07)

| # | 지적 | 검증 방법 | 판정 | 조치 |
|---|---|---|---|---|
| 1 | `CalibMaxIntermediateOutputs`가 범위를 계산하지 않고 버림 → 256장 중 16장만 사용 | ORT 1.25 `calibrate.py` 소스 확인: `collect_data`가 N개 쌓이면 `clear_collected_data()`(목록 비우기)만 호출. 32배치·N=3 → 마지막 2배치(16장)만 남음. 고친 코드로 다시 보정하니 활성값 87개 중 46개의 scale이 10% 이상 커짐(최대 1.89배) | **맞음 (치명)** | 옵션과 우회 루프 삭제. 보정 중 최대 메모리 3.4 GB로 문제없음. **기존 MinMax 모델은 전부 무효** |
| 2 | VNNI 없는 x86에서 U8S8 정수 커널 포화 오차 | `/proc/cpuinfo`: 이 서버는 `avx512_vnni`, `avx_vnni` 있음 → 포화 없음. 하지만 정수 커널과 fake-quant 출력이 코사인 0.993 수준으로 다름(실측) | **부분적으로 맞음** (우리 서버는 해당 없음, 다른 PC에서 숫자가 달라질 위험은 사실) | `evaluate.py --exec fake`(기본): 그래프 최적화 끄고 Q/DQ 그대로 실행. 속도만 정수 커널. 결과에 `exec` 기록 |
| 3 | 고화질 2000장 부분집합이 test → 설정 선택에 test 사용 | 사실. ImageNetV2 보정 후보도 test였음 | **맞음** | dev = 각 데이터셋 train/validation 분할(해시 선택 약 1000장), 보정 후보 = dev와 겹치지 않는 train 사진. test는 최종 1회만. ImageNetV2는 최종 보고 전용 |
| 4 | `--tag` 없으면 다른 설정이 같은 이름으로 덮어씀 | 코드 확인 | **맞음** | 파일 이름에 그래프 변형·보정 방법·출처·장수·시드 자동 포함, 같은 이름이면 `--overwrite` 없이는 중단 |
| 6 | mix 보정 사진이 출처·클래스 순으로 몰림 | 코드 확인. 다만 순수 MinMax(전역 최소·최대)는 순서와 무관하고, 순서가 문제 되는 건 이동평균과 1번 버그가 있을 때 | **맞음 (영향은 제한적)** | 모든 보정 사진을 시드 고정으로 섞음 |

## 수정 효과 확인 (CIFAR 검증 A 1000장, 실험 D 구성)

| 모델 | 실행 | top-1 | 원본과의 유사도 |
|---|---|---|---|
| 기존 (16장 보정, 버그) | 정수 커널 | 38.5 | 0.8445 |
| 기존 (16장 보정, 버그) | fake-quant | 39.2 | 0.8438 |
| 수정 (256장 보정) | 정수 커널 | 36.1 | 0.8344 |
| 수정 (256장 보정) | fake-quant | 37.1 | 0.8338 |

- 보정 사진을 제대로 다 쓰니 **오히려 조금 나빠졌다.** MinMax는 가장 튀는 값까지 담으려고 범위를 넓히는데, 사진이 많을수록 튀는 값을 만날 확률이 커져 눈금이 성글어지기 때문. 16장일 때는 우연히 범위가 좁았던 것.
- → MinMax 대신 튀는 값을 버리는 보정(percentile/entropy)이나 층별 범위 조정이 필요하다는 근거.
- 같은 모델이라도 실행 방식에 따라 top-1이 0.7~1.0%p 다름 → 정확도는 항상 같은 방식(fake)으로 비교.

## 재측정이 필요한 결과
기존 MinMax 모델로 얻은 결과(INT8 전체, 실험 D, D_q1, 단계별 민감도, stem 조합, 누적 ①~⑤, 외부 데이터셋 비교)는 **방향성 참고용**으로만 쓰고, 고친 코드로 다시 잰다. FP32 베이스라인(양자화 없음)은 영향 없음.
