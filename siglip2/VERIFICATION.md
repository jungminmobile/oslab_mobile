# 3중 확인 체크리스트

"한 번 돌려서 숫자가 나왔다"는 완료가 아니다. 아래 세 단계를 거친 것만 결과로 기록한다.

| 단계 | 누가 | 무엇을 |
| --- | --- | --- |
| 1. 자기 검증 | 작업한 Claude Code | 실행 + 불변식 assert + 같은 명령 재실행 |
| 2. 독립 재계산 | 작업한 Claude Code | 핵심 숫자를 다른 경로로 다시 구해 대조 |
| 3. 독립 검토 | 서브에이전트 또는 새 세션 | 맥락 없이 diff·raw 결과만 보고 아래 체크리스트로 반박 시도 |

결정 사항은 3단계 뒤에 사람 승인을 받아야 "확정"이다.

## A. 코드 변경

1단계
- [ ] 작은 입력(예: 이미지 8장)으로 끝까지 실행, 출력 shape·dtype·개수 assert
- [ ] 같은 명령을 두 번 실행해 정확도·임베딩이 비트 단위로 같은지 (결정적이어야 하는 부분)
- [ ] 경로 하드코딩, 숨은 기본값, 무시된 인자 없음

2단계
- [ ] 알려진 답이 있는 경우와 대조 (PyTorch 원본, 공개 보고치, RN50 트랙의 같은 함수 출력)

3단계 검토자 체크리스트
- [ ] 데이터 누수: test가 선택·튜닝·보정에 쓰이지 않았는가
- [ ] 분할·seed가 RN50 트랙과 같은가
- [ ] 보정 장수가 의도와 같은가 (로그로 확인)
- [ ] 전처리(리사이즈, 크롭, 정규화 평균·표준편차)가 모델 카드와 같고 모든 백엔드에서 같은가
- [ ] 정확도가 정수 커널 결과인가 (fake-quant 경로가 섞이지 않았는가, jsonl `exec`가 `int`인가. D-008)
- [ ] 예외를 삼키는 try/except, 조용히 건너뛰는 데이터가 없는가

## B. 실험 결과

1단계
- [ ] 데이터셋 장수가 기대값과 같은가 (분할별)
- [ ] 정확도 재실행 일치, 속도는 PRD 5절 조건(워밍업 20, 200장 × 3회 번갈아, D-017) 평균·표준편차·변동계수 기록
- [ ] `env.json` (CPU 플래그 포함), 커밋 해시, 실행 명령이 결과 폴더에 있는가

2단계
- [ ] FP32: 공개 보고치와 차이가 1%p 이내인가. 아니면 원인부터 찾는다
- [ ] ONNX vs PyTorch 임베딩 코사인 ≥ 0.9999
- [ ] 요약 표의 숫자를 raw 파일에서 별도 스크립트로 다시 계산해 일치
- [ ] 파라미터 수·GMACs를 두 가지 방법으로 계산해 일치 (예: 모델 순회 합계 vs 프로파일러)

3단계 검토자 체크리스트
- [ ] 결론이 숫자에서 직접 따라 나오는가, 다른 해석은 없는가
- [ ] 비교 대상이 같은 조건(PC, 스레드, 보정, 프롬프트)인가. 이 PC 속도는 "비공식"으로 표시했는가 (D-010)
- [ ] 차이가 측정 잡음(표준편차)보다 큰가
- [ ] 이상치가 있으면 원인 가설이 적혀 있는가

## C. 결정

- [ ] 대안을 2개 이상 적었는가
- [ ] 근거 데이터의 경로·커밋이 연결돼 있는가
- [ ] "이 결정이 틀렸다면 어떤 데이터가 보일까"를 적고, 그 데이터가 실제로 없는지 확인했는가
- [ ] 되돌리는 비용과 마감 영향
- [ ] 사람 승인 (DECISIONS.md 상태를 확정으로 바꾸는 것은 승인 후에만)

## D. 단계별 추가 확인

- G1: opset, 입력 shape 고정, ONNX 연산 목록, DFC 버전과 전체 로그 보관, 컨텍스트 수
- G2: 프롬프트 템플릿 비교가 dev에서만 이뤄졌는가, test는 1회만
- G3: 양자화된 그래프에서 어떤 연산이 실제로 정수인지 노드 목록, 보정 장수 assert
- G4: DFC 버전, model script(.alls) 전문을 결과 폴더에 보관, 에뮬레이터 vs ORT 차이 설명
- G5(본선 Pi): monitor off, 온도 로그, `OPENBLAS_NUM_THREADS=1`, run 수 정의, 기기 설정 변경 없음 확인
- G6: VNNI 없는 CPU에서의 정확도, 클린 환경 재현, test 평가가 정말 1회인지 기록 확인

```
3. 독립 검토: <검토자가 지적한 것과 처리 결과>
```
